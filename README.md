# learn-notes · 바이브코딩 학습 노트

Claude가 코드를 고치면 **바뀌기 전과 후**를 모아 두었다가, 턴이 끝날 때마다
"무엇이 왜 바뀌었고 무엇을 배울 수 있는지"를 **학습 노트**로 정리해 오른쪽 패널에 보여 주는
[Claude Code](https://code.claude.com) 모드(mod)입니다.
코드가 하던 일과 이제 하는 일을 **전/후 한 줄씩과 예시**로 보여 주고, 바뀐 줄에서는 **바뀐 낱말까지** 표시합니다.
노트 끝의 **직접 해 보기**로 내 코드 한 줄을 패널 안에서 고쳐 보고 바로 확인받습니다. 프로젝트 파일은 바뀌지 않습니다.
배운 개념은 프로젝트를 넘어 쌓이고, 잊을 때쯤 **내가 만든 코드로** 복습 퀴즈를 냅니다.
답을 적고 Enter를 누르면 Claude가 채점합니다. 첫 답이 틀리면 정답 대신 **되묻기**가 먼저 나와 한 번 더 떠올려 봅니다.
그래도 헷갈린 점은 **오답 노트**에 남아, 다음 퀴즈가 다른 코드로 그 자리를 다시 묻습니다.
`.env` 같은 비밀 파일은 노트에 싣지 않고, 코드 속 흔한 키 형식은 `«가림»`으로 가립니다.

<sub>사용 흐름을 보여 주는 데모입니다. 장면마다 모드의 테스트 키트로 엔진이 실제로 그린 화면을 이어 붙였고, 노트·되묻기·퀴즈·채점은 모두 이 모드의 프롬프트로 haiku가 실제로 쓴 글입니다.</sub>

> **English**: A Claude Code mod for learning while you vibe-code. After each turn in which Claude edits files, a small
> model (haiku by default) writes a short Korean study note: before/after with an example, why, concepts, and one line
> of your code to change yourself in the pane (files on disk are never touched). Review with spaced-repetition quizzes
> built from your own code and graded by Claude; a first wrong answer gets a question asked back and one more try.
> A team glossary becomes practice on the team's code, `c` copies a note for a mentor without paths, and
> `/learn 진단` (doctor) gives a code-free diagnosis. Secret, lock and generated files stay out; key formats are masked.

## 빠른 시작

Claude Code **v2.1.289 이상**이 필요합니다 (`claude --version`).

1. Claude Code 안에서 두 줄을 입력해 설치합니다.

   ```
   /plugin marketplace add Owen-YC/learn-notes
   /plugin install learn-notes@learn-notes
   ```

2. Claude Code를 다시 시작합니다. 터미널에서는 `/tui fullscreen`으로 전체 화면으로 바꿉니다. 패널이 대화 오른쪽에 붙으려면 전체 화면이어야 합니다. 데스크톱 앱은 바꿀 것 없이 오른쪽에 붙습니다.
3. `/learn`으로 패널을 엽니다. 키는 대화 입력칸에 그대로 있어서, 이어서 치는 글은 Claude에게 가는 요청이 됩니다.
   패널의 키를 쓰려면 `ctrl+x tab`을 누르거나 패널을 클릭합니다. `Esc`를 누르면 대화 입력칸으로 돌아갑니다(패널은 그대로 있습니다).
4. 평소처럼 코딩을 요청합니다. 예: `hello.js에 이름을 받아 인사하는 함수를 만들어 줘`. Claude가 파일을 고친 턴이 끝나면 몇 초 안에 노트가 뜹니다.
5. **오늘 복습은 `/learn 복습`** 한 번이면 됩니다. 패널이 퀴즈로 열리고 커서가 `내 답` 칸에 있어서 바로 답을 적습니다.

키를 누를 때 하나만 기억하세요. **숫자 `1`~`4`는 한/영 상태와 상관없이** 눌리고, `q`·`t`·`c` 같은 **글자 키는 영문 상태**에서 누릅니다. 한글 상태면 `q`가 `ㅂ`으로 들어가 단축키가 먹지 않습니다.

`/learn 도움말`의 첫 줄이 `learn-notes 1.7.1 명령`이면 제대로 켜진 것입니다. 대화 입력칸에 `/learn `까지 치면 `[복습|퀴즈|정리|질문|기록|보고서|공유|진단|도움말]`이 힌트로 보입니다. 처음 설치한 세션에서는 `learn-notes가 켜졌습니다 · 파일을 고치는 요청을 하면 노트가 생깁니다 · /learn으로 패널` 알림이 한 번 뜹니다.

- **업데이트**: 먼저 **플러그인 목록을 새로 받습니다**. Update now도 목록을 새로 받아 보지만, 그게 안 되면 옛 목록으로 판단하므로 먼저 받아 두면 확실합니다.
  - Claude Code 안에서: `/plugin` → Marketplaces → learn-notes → **Update marketplace**, 그다음 Installed → learn-notes → **Update now**(그 위의 Mark for update는 표시만 해 둡니다), 마지막으로 `/reload-plugins`.
  - 터미널(PowerShell)에서: `claude plugin marketplace update learn-notes` 다음 `claude plugin update learn-notes@learn-notes`, 그리고 열려 있던 창에서 `/reload-plugins`(또는 다시 시작).
  - `/learn 도움말` 첫 줄의 판 번호로 확인합니다. 패널에 `v: 전/후`나 `t: 이 노트 퀴즈`가 보이면 아직 1.6 이하입니다.
  열려 있던 다른 창에 `learn-notes 새 버전(1.7.1)이 다른 창에서 쓰이고 있습니다 · 이 창은 1.7.0입니다 · /reload-plugins로 바꿉니다` 알림이 뜨면 그 창에서 **`/reload-plugins`를 실행합니다**.
  이 알림은 1.7.0부터 있습니다. 1.6.x에서 올릴 때는 열려 있던 창마다 `/reload-plugins`를 한 번 실행하거나 다시 시작하세요.
- **지우기**: `claude plugin uninstall learn-notes@learn-notes` (일지 파일 `~/.claude/learning-notes/`는 남습니다). **설치 없이 한 번 써 보기**: 이 저장소를 받아 `claude --plugin-dir <저장소 경로>`로 시작합니다.
- **Windows**: PowerShell에서 `irm https://claude.ai/install.ps1 | iex`로 Claude Code를 설치한 뒤 위와 똑같이 씁니다.
  Claude Code는 **작업할 폴더에서** 켜세요(`cd ~\practice` 뒤 `claude`). 관리자 PowerShell처럼 `C:\Windows\System32`에서 켜면 Claude가 파일을 임시 폴더에 만듭니다. 이때도 노트는 생기고, 패널 맨 위에 작업 폴더에서 켜라는 안내가 뜹니다. `claude`를 못 찾으면 새 창을 열거나 `$env:Path += ";$HOME\.local\bin"`을 입력하세요.
- **VS Code 확장**에는 패널이 없습니다. `/learn`은 마지막 노트를 대화창에 적어 줍니다. 패널을 보려면 같은 폴더의 터미널(VS Code 아래 터미널도 됩니다)에서 `claude`를 켜거나 데스크톱 앱에서 그 폴더를 열고 `/learn`을 칩니다. 노트는 폴더마다 쌓이므로 거기서도 같은 노트가 보입니다.
- **클라우드 세션**(claude.ai 웹·앱에서 여는 Claude Code 세션)은 클라우드 컴퓨터에서 돌아 노트도 그 컴퓨터에 쌓입니다(내 컴퓨터의 `/learn`에는 나오지 않습니다). 웹·휴대폰에서는 패널이 보는 화면에 뜨지 않을 수 있고, 데스크톱 앱에서 연 클라우드 세션은 패널이 오른쪽에 붙을 수 있습니다. 패널이 없으면 노트가 준비될 때 대화창에 흐린 줄(`학습 노트 · 한 줄 요약 · /learn으로 보기`)이 남고, `/learn`은 마지막 노트를 대화창에 적어 줍니다. 퀴즈·질문도 명령(`/learn 복습`, `/learn 퀴즈 1 내 답`, `/learn 질문 …`)으로 다 됩니다. 직접 해 보기는 데스크톱 앱에서 그 세션을 열어 패널에서 합니다.

## 하는 일

1. **모읍니다.** Claude가 `Edit`·`Write`, 또는 파일을 바꾸는 셸 명령(Bash, Windows에서는 PowerShell)을 쓸 때마다 바뀐 내용을 모읍니다. 턴이 도는 동안 패널 맨 위에 `● 작업 중: 파일 n개`가 보입니다.
   비밀값이 들 수 있는 파일(`.env` 등)과 잠금·생성 파일(`package-lock.json` 등)은 **이름만 남기고 내용은 모으지 않습니다.** 다른 파일 속 흔한 키 형식은 `«가림»`으로 바꿉니다.
2. **노트를 씁니다.** 턴이 끝나면 저렴한 모델(기본 `haiku`)이 바뀐 코드와 내 요청, Claude의 마지막 설명을 읽고
   다섯 칸짜리 노트를 씁니다: **한 줄 요약 · 무엇이 바뀌었나 · 왜 이렇게 바꿨을까 · 배울 개념 · 직접 해 보기**.
   "무엇이 바뀌었나"는 코드 설명 대신 **전**(하던 일) · **후**(이제 하는 일) · **예**(차이가 드러나는 입력과 결과) 세 줄로 씁니다.
   서버가 잠깐 붐비거나 연결이 끊겨 실패하면 30초 뒤 한 번 더 씁니다.
3. **패널에서 봅니다.** 숫자 키 `1`~`4`로 노트, 바뀐 낱말까지 표시한 전/후, 지금까지 배운 개념, 퀴즈를 오갑니다. 지난 세션의 노트도 그대로 남아 있습니다.
4. **쌓습니다.** 노트는 날짜별 마크다운 일지(`~/.claude/learning-notes/`)에, 배운 개념은 프로젝트를 넘어 한 목록(`concepts.md`)에 쌓입니다.
5. **복습합니다.** 개념마다 다음 복습 날짜가 있어, 때가 되면 내가 만든 코드로 문제를 냅니다. 상태줄에 `학습 노트 · 오늘 복습 n개 · /learn 복습`이 보이면 `/learn 복습`으로 바로 시작합니다(패널에서는 `q`).

## 패널 사용법

### 키 한눈에

| 키 | 하는 일 |
| --- | --- |
| `1` · `2` · `3` · `4` | 보기 바꾸기: 노트 · 전/후 · 개념 모음 · 퀴즈 |
| `q` | 오늘 복습 바로 시작 (보기 줄 끝에 `q: 복습 n개`가 보일 때) |
| `p` · `n` | 이전 · 다음 노트 (지난 세션 노트까지) |
| `t` · `e` · `r` · `i` · `c` | 노트 아래에서: **직접 해 보기**(한 번 고친 뒤 `a` 예시 답) · 더 쉽게 · 예시로 따라가기 · 질문하기 · **복사** ([노트 아래에서 바로](#노트-아래에서-바로)) |
| `w` | 노트 쓰기 · 다시 쓰기 (자동 노트가 다시 쓰기를 기다리는 동안에는 `바로 쓰기`) |
| `Esc` | 대화 입력칸으로 돌아가기 (패널은 그대로) |
| `ctrl+x tab` | 대화 입력칸에서 패널로 (패널 클릭도 됩니다) |

퀴즈 보기의 키는 [퀴즈 풀기](#퀴즈-풀기)에 있습니다. 버튼 앞에 키가 적혀 있고(`2: 전/후`), 마우스로 눌러도 됩니다. `/learn 도움말`도 패널이 그리는 키를 모두 줄마다 모아 보여 줍니다.
보기 줄 아래에는 지금 키가 어디 있는지가 흐리게 보입니다. 키가 대화에 있으면 `ctrl+x tab: 패널 고르기 · 숫자 키는 한/영 상관없이, 글자 키는 영문 상태에서`, 패널에 있으면 `Esc: 대화로 돌아가기 · 글자 키는 영문 상태에서`입니다(처음 설치해 노트도 개념도 없을 때는 안내 글만 있습니다).

### 보기 바꾸기

패널 위쪽 보기 줄은 늘 `1: 노트 · 2: 전/후 · 3: 개념 모음 · 4: 퀴즈`입니다. 지금 보는 보기는 굵게 밑줄이 쳐집니다. 보기 이름을 클릭해도 됩니다. 노트가 아직 없으면 `2: 전/후`만 빠지고 번호는 그대로입니다.

오늘 복습할 개념이 남아 있으면 보기 줄 끝에 노란 `●`와 `q: 복습 3개`가 붙습니다.
`q`를 누르면 퀴즈 보기로 가고, 풀던 문제가 있으면 그 문제의 답 칸으로, 없으면 `문제를 만드는 중입니다…`가 뜨면서 새 문제를 받습니다. 대화 입력칸의 `/learn 복습`은 패널을 열면서 이 `q`까지 한 번에 합니다.

노트 보기와 전/후 보기 맨 위에는 `노트 2/5 · 10:12 · 파일 2개 · +5 −1`처럼 지금 노트의 자리와 바뀐 양이 나옵니다.
노트에서 뺀 파일이나 가린 비밀값이 있으면 그 아래 줄에 `노트에서 뺀 파일 1개 · 비밀값 1곳 가림`이 흐리게 나옵니다. 그 아래 `◀ 이전`(`p`) · `다음 ▶`(`n`)으로 노트를 오가고, `요청:` 줄에 그 턴의 요청이 보입니다.

### 전/후: 무엇이 달라졌는지 한눈에

노트의 **무엇이 바뀌었나**는 코드가 하던 일(`− 전`, 빨강)과 이제 하는 일(`+ 후`, 초록), 그 차이가 드러나는 예(`→ 예`)를 한 줄씩 보여 줍니다.
**전/후** 보기(`2`)는 맨 위에 그 세 줄을 다시 보여 주고, 바뀐 곳마다 원래 코드(전)와 바뀐 코드(후)를 파일의 줄 번호 그대로 놓습니다.

- 바뀌지 않은 줄은 흐리게, 바뀐 줄은 앞에 `−`(전) · `+`(후)를 붙입니다.
- 한 줄을 고친 것이면 **그 줄에서 바뀐 낱말만 굵은 색**으로 표시합니다. 예: `var n = 0` → `let n = 0`에서는 `var`와 `let`만.
- 거의 새로 쓴 줄은 줄 전체를 색으로, 새로 만든 파일은 코드 그대로 보여 줍니다.
- 맨 아래에는 노트에서 뺀 파일이 이름과 까닭으로 나옵니다. 예: `노트에서 뺀 파일: .env (비밀값이 들 수 있는 파일) · package-lock.json (잠금·생성 파일)`

### 노트 아래에서 바로

노트 맨 아래는 `이 노트로` 키 줄 → 지난 질문과 답 → `질문:` 칸 → 직접 해 보기(펼쳤거나 마쳤을 때) 순서입니다.

- `t` **직접 해 보기**: 노트의 한 줄을 패널에서 고쳐 봅니다. 아래 [직접 해 보기](#직접-해-보기-t)에 있습니다.
- `e` **더 쉽게**: 원래 노트는 그대로 두고, 노트 아래에 `▶ 더 쉽게`로 쉬운 말과 일상의 비유를 넣은 설명을 덧붙입니다. 설정한 설명 수준과 상관없이 입문자 기준으로 씁니다.
- `r` **예시로 따라가기**: 예시 입력 하나로 바뀐 코드를 한 단계씩 따라갑니다(`▶ 예시로 따라가기`). 단계마다 변수 값이 어떻게 바뀌는지, 바뀌기 전 코드였다면 어디서 결과가 갈리는지 짚어 줍니다.
- `i` **질문하기**: `질문:` 칸에 궁금한 것을 적고 Enter. 그 노트와 코드를 근거로 짧게 답하고, 답은 노트 아래에 남습니다. 이어서 물으면 앞의 질문과 답을 읽고 답합니다. 대화창의 Claude와 달리 코드를 고치지 않고, 저렴한 모델이 답합니다.
- `c` **복사**: 요청·질문·코드 블록·경로를 뺀 노트 글을 클립보드에 복사합니다([노트 복사해 멘토에게 묻기](#노트-복사해-멘토에게-묻기-c--learn-공유)).
- `w` **다시 쓰기**: 노트를 처음부터 다시 씁니다. 다시 쓰다 실패하거나 다시 불러오기(`/reload-plugins`)로 끊기면 원래 노트를 그대로 둡니다. 다시 쓴 노트의 직접 해 보기는 새 연습이 됩니다.

`e`·`r`·질문은 할 때마다 모델 호출 한 번이고, 개념 수와 학습 기록은 바뀌지 않습니다. 이때 모델에게는 직접 해 보기의 고칠 줄과 예시 답을 보내지 않습니다. 노트 아래에는 최근 질문과 답 2개가 보이고(노트마다 3개까지 남음), 그보다 오래된 것은 일지에 있습니다.

### 직접 해 보기 (`t`)

노트 끝 칸 **직접 해 보기**에는 할 일과 확인만 보입니다. `t`를 누르면 모델을 부르지 않고 `질문:` 칸 아래에 연습 칸이 펼쳐지고, 커서가 칸에 갑니다.

```
직접 해 보기 · hello.js
- 할 일: 이름이 비어 있으면 "손님"에게 인사하게 바꿔 보세요
- 확인: greet("") → "안녕하세요, 손님!"
  ⋮
이 노트로  t: 직접 해 보기  e: 더 쉽게  r: 예시로 따라가기  i: 질문하기  c: 복사  w: 다시 쓰기
질문: 궁금한 것을 적고 Enter
✎ 연습입니다 · 파일은 바뀌지 않습니다
Enter: 확인 · 코드는 영문 상태에서 · Tab: 버튼으로 (1~4 보기)
11  function greet(name) {
12: return `안녕하세요, ${name}님!`
13  }
```

- 칸 앞의 숫자는 파일의 줄 번호이고, 위아래 줄은 흐리게 보입니다. 칸에는 원래 줄이 미리 들어 있어서 그 줄을 고치면 됩니다.
- 칸 바로 위의 흐린 안내 줄이 Enter로 무엇을 하는지와 영문 상태를 알려 줍니다. Enter 뒤의 알림(`아직 바꾼 곳이 없습니다 …` 등)도 이 줄 위에 뜹니다. 칸이 패널 맨 아래에 와도 잘리지 않게 칸 위에 둡니다.
- 코드는 **영문 상태**에서 적습니다. 칸에 커서가 있는 동안에는 글자와 숫자가 칸에 들어가므로, 보기를 바꾸려면 `Tab`으로 버튼에 간 뒤 누릅니다.
- 패널이 키를 받으면(`ctrl+x tab`, 클릭, 다음 세션) 연습 칸이 먼저 키를 받습니다. 영문으로 친 코드가 `r`·`e`·`w` 같은 노트 단축키로 눌리지 않습니다. 키가 대화에 있는 동안 터미널에서는 칸 위 안내 줄 끝이 `· ctrl+x tab: 고칠 줄 칸으로`입니다(데스크톱 앱에는 이 꼬리가 없습니다).
- 고친 줄을 적고 Enter를 누르면 이렇게 됩니다.
  - 고치지 않았으면 `아직 바꾼 곳이 없습니다 · 줄을 고친 뒤 Enter`, 한글 상태로 쳤으면 `코드는 영문 상태에서 적습니다`, 칸을 비웠으면 `줄이 비었습니다 · 고친 줄을 적고 Enter · 모르겠으면 '모르겠어요'` (모두 호출 없음)
  - 노트의 예시 답과 같으면 바로 `✓ 해냈습니다` (호출 없음)
  - 다르게 고쳤으면 `확인하는 중입니다…` 뒤 Claude가 할 일과 확인대로 되는지 봅니다. 되면 `✓ 해냈습니다`와 `예시 답과 견주기: …`가 나옵니다.
  - 아직이면 퀴즈처럼 `✗ 아직입니다 · 한 번 더 고쳐 보세요`(방향이 맞으면 `△ 아직입니다 · 방향은 맞습니다`)와 **되묻기**가 나오고, 새 칸에 내 줄이 남아 한 번 더 고칩니다.
  - `모르겠어요`라고 적으면 호출 없이 힌트(`할 일과 확인을 다시 읽고, 이 줄에서 바꿀 곳 한 군데를 찾아보세요`)가 나오고 한 번 더 고칩니다.
- 두 번째 확인으로 끝납니다: `✓ 해냈습니다 · 되짚어 맞힘` · `△ 거의 맞음` · `✗ 틀림`. 피드백과 `내 줄: …`이 남습니다. 첫 확인에 되묻기가 붙지 않으면 첫 확인으로 끝납니다. 끝난 연습은 다시 풀 수 없습니다.
- `a` **예시 답**은 한 번 고쳐 본 뒤에 나옵니다. 한 번 더를 기다릴 때 누르면 첫 판정대로 끝나고 `· 예시 답 봄`이 붙습니다. 끝난 뒤 맞히지 못했으면 `a`로 예시 답만 펼쳐 봅니다. 빠르게 두 번 눌러도 한 번만 매깁니다.
- 휴대폰 앱처럼 입력칸이 없는 화면에는 `t`가 없고 노트 줄에 `a: 예시 답`만 있습니다. 거기서 `a`를 누르면 매기지 않고 예시 답만 펼치며, 그 연습은 끝난 것으로 남습니다. 터미널에서 한 번 더를 기다리는 연습이면 `한 번 더는 터미널·데스크톱 패널에서 고칩니다 · a: 예시 답`이 보입니다.
- 고칠 줄이 없는 변경(설정·스타일·문서 등)이면 노트에 이 칸이 없고 `t`도 없습니다. 노트가 적은 고칠 줄을 바뀐 코드에서 찾지 못했거나 40자를 넘으면 할 일과 확인만 글로 남고 `t`는 없습니다. 1.7.0 전에 쓴 노트(`직접 확인해 볼 것` 칸)에도 `t`가 없습니다.

**매김**: 연습은 노트가 처음 적은 개념 하나를 퀴즈처럼 매깁니다(아는 개념이면 매기지 않음). 맞히면 퀴즈와 같은 규칙으로 한 단계 오르고, 되짚어 맞힘 · 힌트 뒤 맞힘 · 예시 답 봄은 단계를 그대로 둡니다. 거의는 한 단계 내리고, 틀리면 처음으로 돌아갑니다.
틀린 연습의 헷갈린 점은 [오답 노트](#오답-노트-헷갈린-점과-다시-도전)에 남습니다. 하루 맞힘·틀림(정답률)에는 세지만 **오늘 복습 10문제 몫에는 세지 않습니다.** 풀던 복습 퀴즈는 건드리지 않습니다.
한 번 더를 기다리다 날이 바뀌면, 다음 세션을 시작할 때 첫 판정대로 그 날짜로 매깁니다.

**어디에 남나**: 고칠 줄과 예시 답은 일지에만 있습니다. 패널의 노트, 복사 글, 학습 기록 도구, 패널 없이 보는 `/learn`의 노트에서는 가립니다. 결과는 노트에(1KB 이하, 내 줄의 비밀값은 가림), `autoSave`가 켜져 있으면 일지에 `## 2026-10-16 직접 해 보기 (10:12)` 절로 남습니다.

### 퀴즈 풀기

`4`로 퀴즈 보기를 열고 `s`로 문제를 받습니다(최대 3문제, 모델 호출 한 번). 복습할 때가 된 개념부터, 그 개념을 배운 노트의 **내 코드**를 보여 주며 묻습니다.
세 문제는 되도록 서로 다른 노트에서 고릅니다. 복습할 개념이 3개보다 적으면 곧 때가 될 개념으로 채우고, 저장소에 [팀 용어](#팀-용어-연습)가 있으면 그 빈자리는 아직 안 만난 팀 용어가 먼저 채웁니다.
지난번에 헷갈린 개념은 때가 되지 않았어도 다음 퀴즈에 `다시 도전`으로 나옵니다([오답 노트](#오답-노트-헷갈린-점과-다시-도전)).

첫 퀴즈 전에는 `s`가 무엇을 낼지 흐리게 알려 줍니다: `s를 누르면 복습할 개념으로 내 코드에서 3문제를 냅니다`, 팀 용어가 빈자리를 채우면 `s를 누르면 복습할 개념과 이 저장소의 팀 용어로 3문제를 냅니다`, 팀 용어만이면 `s를 누르면 이 저장소의 팀 용어로 3문제를 냅니다`(개념과 용어가 모자라면 그 수만큼).

문제 제목에 유형이 붙습니다(`문제 1/3 · 예측`). **예측**은 코드를 보여 주고 출력이나 값을 맞히게 합니다(값이 같으면 설명이 없어도 맞힘). **왜**는 어떤 줄을 빼거나 바꾸면 어떻게 되는지, 왜 그렇게 썼는지 묻습니다. **바꿔 보기**는 바라는 동작을 말하고 어느 줄을 어떻게 바꿀지 묻습니다(바라는 대로 동작하면 정답과 다른 코드여도 맞힘).

**답은 적고 Enter**: 문제가 나오면 커서가 `내 답` 칸에 있습니다. 패널로 키를 옮길 때(`ctrl+x tab`·클릭·`/learn 복습`)도 풀던 문제의 `내 답` 칸에서 시작합니다. 답을 적고 Enter를 누르면 `채점하는 중입니다…` 뒤 Claude가 정답과 비교해 채점합니다. 한/영을 바꾸지 않고 한글로 답을 적으며 이어 풀 수 있습니다.
채점이 끝나면 커서가 다음 문제의 `내 답` 칸으로, 마지막 문제 뒤에는 `s: 새 문제 받기`로 갑니다.

**첫 답이 틀리면 되묻기와 한 번 더**: 첫 답이 거의 맞거나 틀렸고 Claude가 되묻기를 붙이면, 정답을 펼치지 않고 같은 자리에 이렇게 나옵니다.

```
△ 아직입니다 · 방향은 맞습니다
내 답: 0 1 2 3
적은 대로라면 i가 3일 때도 찍혀야 합니다.
되묻기: i가 3이 되면 i < 3은 참일까요?
내 답 (한 번 더): [                    ]
Enter: 다시 채점 · Tab: 버튼으로 (a 정답 · f 맞았는데요)
```

- 틀린 첫 답은 `✗ 아직입니다 · 한 번 더 떠올려 보세요`로 시작합니다. 커서는 빈 `내 답 (한 번 더)` 칸에 있어 한/영을 바꾸지 않고 다시 적으면 됩니다.
- 두 번째에 맞히면 `✓ 맞힘`과 `· 되짚어 맞힘`, 피드백·정답이 나옵니다. 두 번째도 틀리면 정답을 펼치고 `✗ 틀림`으로 매깁니다. 두 번 다 '거의'였으면 `△ 거의 맞음`입니다.
- 되묻기가 붙지 않은 답(되묻기가 정답을 그대로 말해 버린 경우 포함)은 바로 채점하고 정답을 펼칩니다.
- 한 번 더를 하지 않고 새 퀴즈를 받거나 날이 바뀌면, 그 문제는 첫 판정대로 그 날짜로 매겨집니다. 날이 바뀌어 매겼으면 다음 세션을 시작할 때 대화창에 흐린 줄 `날이 바뀌어 한 번 더를 기다리던 1번 (✗ 틀림)은 첫 답의 판정대로 매겼습니다.`가 한 번 남습니다(Claude에게 가지 않음). 대화창 `/learn 퀴즈`에서는 답 앞에 같은 문장이 붙습니다.
- 새 문제를 만드는 동안(`s` 두 번, `/learn 퀴즈 새로` · `팀`)에는 답 칸의 Enter를 받지 않고 빨간 `새 문제를 만들고 있습니다. 문제가 나온 뒤 답하세요.`가 뜹니다. 적은 답은 칸에 남습니다.

**모르겠으면 `모르겠어요`**: `모르겠어요` · `몰라` · `모름` · `?`만 적고 Enter를 누르면 **모델을 부르지 않습니다.** 힌트가 남았으면 되묻기 자리에 힌트를 보여 주고(`힌트를 보고 한 번 더 떠올려 보세요`) 한 번 더 답합니다. 힌트를 이미 봤거나 없으면 정답을 펼치고 `✗ 틀림`으로 매깁니다. (`??`는 JS의 연산자일 수 있어 답으로 채점합니다.)
빈 칸에서 Enter를 누르면 `모르겠으면 '모르겠어요'라고 적고 Enter · 막히면 h로 힌트`가 뜹니다.

**답 칸 아래 안내**: 터미널에서 패널이 키를 받고 있으면 `답 칸에서 Enter: 채점 · 모르면 '모르겠어요' · Tab: 버튼으로 (h 힌트 · 1~4 보기)`입니다. 칸에 커서가 있는 동안 글자와 숫자는 답으로 들어가므로, `Tab`으로 버튼에 간 뒤 `h`·`1`~`4`를 누르거나 버튼을 마우스로 누르세요. 위 문제의 `n`이 있으면 `n 배운 노트`도 붙습니다.
데스크톱 앱, 키가 대화에 있는 터미널 패널에서는 이 줄 대신 `모르면 '모르겠어요'라고 적고 Enter`가 보입니다.
답 칸이 기다리는 동안 보기 줄 아래 안내도 바뀝니다: 키가 대화에 있으면 `ctrl+x tab: 답 칸으로 · 보기를 바꾸려면 그 뒤 Tab · 글자 키는 영문 상태에서`, 패널에 있으면 `Esc: 대화로 돌아가기 · 답은 한/영 상관없이, 버튼의 글자 키는 영문 상태에서`.

| 키 | 하는 일 |
| --- | --- |
| `h` | 힌트: 답을 말하지 않고 떠올릴 실마리만 (첫 답 전에) |
| `i` | 답 칸으로 가기 |
| `a` | 정답 보기. **한 번 적어 본 뒤에** 나오고, 첫 판정대로 바로 매깁니다(거의면 `△`, 틀림이면 `✗`) |
| `f` | 되묻기 화면에서는 `맞았는데요`: 첫 답을 맞힘으로 매깁니다. 채점된 문제에서는 채점 바꾸기: 맞힘 ↔ 틀림을 바꾸고 복습 단계도 처음부터 그렇게 채점한 것처럼 돌아갑니다 |
| `n` | 이 개념을 배운 노트로 가기: Claude가 틀림·거의로 채점한 문제 아래에 나옵니다. 그 노트에서 `r`로 코드를 따라가 보세요. 노트가 패널에 없으면 `/learn 찾기 개념 이름`을 안내합니다 |
| `s` | 새 문제 받기 (처음에는 `퀴즈 시작`). 풀던 문제가 남았으면 `풀던 문제 n개가 남았습니다 · s를 한 번 더 누르면 새 문제를 받습니다`가 뜨고, 바로 한 번 더 눌러야 새 문제를 받습니다 |
| `o` · `x` | 정답을 **채점 전에** 봤을 때만: 맞혔어요 · 틀렸어요로 스스로 채점. 입력칸이 없는 화면(모바일 앱), 채점 호출이 실패한 문제, 대화창에서 `/learn 퀴즈 정답`을 본 문제가 그렇습니다 |

채점한 문제는 위에 `✓ 맞힘` · `△ 거의 맞음` · `✗ 틀림` 한 줄로 남습니다. 힌트를 봤으면 `· 힌트 봄`, 되묻기 뒤에 맞혔으면 `· 되짚어 맞힘`, 정답을 보고 맞힘으로 채점했으면 `· 정답 봄`이 붙습니다. 방금 Claude가 채점한 문제는 다음 문제를 채점할 때까지 피드백·내 답·정답이 펼쳐져 있습니다.
퀴즈와 채점은 저장되므로 Claude Code를 다시 켜도 이어서 풉니다. 모바일 앱은 입력칸이 없어 `a`·`o`·`x`로 풀거나, 대화창에 `/learn 퀴즈 1 내 답`으로 답합니다. 되묻기가 남은 문제는 모바일에서 `a`·`f`와 `한 번 더: /learn 퀴즈 1 새 답`이 보입니다.

### 오답 노트: 헷갈린 점과 다시 도전

새 키, 새 보기, 새 명령은 없습니다. Claude가 채점할 때 틀린 생각을 한 문장으로 남기고, 다음 퀴즈가 그 자리를 다른 코드로 다시 묻습니다.

**채점 직후** 피드백 아래에 흐린 한 줄이 붙습니다.

- 틀림·거의로 끝났으면(되묻기 뒤 두 번째 답 포함): `헷갈린 점: const면 배열 안도 못 바꾼다고 봄 · 다음 퀴즈에서 다른 코드로 다시 묻습니다`
- 되묻기 뒤 맞혔으면: `헷갈린 점을 바로 고쳤습니다 · 다른 날 다른 코드로 한 번 더 확인합니다`
- 답이 비었거나 `모르겠어요`였으면: `떠오르지 않았습니다 · 다음 퀴즈에서 다시 풉니다`
- 두 글자 이하의 짧은 답이면: `답이 짧아 헷갈린 점은 적지 않았습니다 · 다음 퀴즈에서 다시 풉니다`

`a`로 정답을 보거나, `/learn 퀴즈 틀림`으로 매기거나, 남은 첫 시도가 첫 판정대로 매겨질 때도 첫 답의 헷갈린 점을 남깁니다. `o`·`x`로 스스로 채점한 답(적은 답이 없음)은 남기지 않습니다. 직접 해 보기의 오답도 같은 곳에 남습니다.

**다음 퀴즈**: 헷갈린 점이 남은 개념은 때가 되지 않았어도 다음 복습 퀴즈에 나오고, 제목이 `문제 1/3 · 다시 도전`입니다(대화창 `/learn 퀴즈`에서는 문제 앞에 `(다시 도전)`). 되묻기 뒤 맞힌 개념은 다음 날부터 나옵니다. 헷갈린 점은 답하기 전에는 보이지 않고, 퀴즈는 지난 문제와 다른 코드로 같은 자리를 묻습니다.

**다시 도전의 결과**:

- 다른 날 힌트·되묻기 없이 맞히면: 초록 `✓ 지난번 헷갈린 점을 바로잡았습니다`
- 같은 날 맞히면: `바로 다시 맞혔습니다 · 다음 복습에서 한 번 더 확인합니다`
- 또 틀리면: `같은 곳을 또 헷갈렸습니다`. 그 개념을 배운 노트가 패널에 있으면 ` · n: 이 개념을 배운 노트 · 거기서 r로 따라가기`가 붙습니다(대화창에서는 ` · 이 개념을 배운 노트: /learn 찾기 이름`).

**보이는 곳**: 개념 모음(`3`)의 '복습할 개념' 줄이 날짜 대신 `const 선언 · 헷갈린 점: 배열 안도 못 바꾼다고 봄`을 보여 줍니다(56칸에서 끝을 자름). 날짜는 `/learn 기록`의 복습 줄에 `(퀴즈 틀림 10-12)`로 남습니다. `/learn 정리`의 '헷갈리기 쉬운 것'도 그 기간에 남은 헷갈린 점으로 씁니다(없을 때만 예전처럼 틀린 개념으로).

**지워지는 때**: `f`로 채점을 맞힘으로 바꾸면 그 채점이 남긴 헷갈린 점이 지워집니다. `/learn 안다`로 표시하거나 졸업하면 바로잡은 것으로 칩니다. 바로잡은 기록은 60일 뒤 지웁니다.

Claude는 헷갈린 점마다 유형(9가지)도 적지만, 지금은 모으기만 하고 화면에는 쓰지 않습니다.
오답 노트는 Claude Code의 플러그인 저장소에만 남습니다(개념 300개·150KB까지). 일지 · `concepts.md` · Anki · 보고서 · 학습 기록 도구에는 싣지 않습니다(다만 `/learn 정리`를 하면 '헷갈리기 쉬운 것'에 그 기간의 헷갈린 점이 적혀, 정리 절과 함께 일지와 대화창에 남습니다).

### 간격 반복 복습

배운 개념은 **잊을 때쯤** 다시 나옵니다. 직접 떠올려 맞힐 때마다 간격이 늘어납니다.

| 단계 | 0 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- | --- |
| 다음 복습 | 1일 뒤 | 3일 뒤 | 7일 뒤 | 14일 뒤 | 30일 뒤 | 60일 뒤 |

- **퀴즈로 떠올린 것만 복습으로 칩니다.** 노트에서 다시 만난 개념(`다시 만난 개념 for...of 반복문 ×3`)은 복습 날짜를 바꾸지 않습니다. 퀴즈를 아직 안 본 개념은 처음 만난 날부터 1일 뒤(노트에서 다시 만났으면 3일 뒤)에 나옵니다.
- 때가 된 개념을 **답을 직접 적어 맞히면** 한 단계 오릅니다. 때가 되기 전에 맞힌 것이나 같은 날 다시 맞힌 것은 단계를 그대로 두고 그날부터 다시 셉니다.
- **힌트·되묻기·정답을 보고** 맞히면(되짚어 맞힘, 정답을 본 뒤 `o`, `/learn 퀴즈 정답` 뒤 `맞음` 포함) 단계는 그대로이고 같은 간격 뒤에 다시 나옵니다. 퀴즈 끝 줄에도 `힌트·되묻기·정답을 보고 맞힌 개념은 같은 간격 뒤 다시 나옵니다`가 나옵니다.
- **거의 맞으면** 한 단계 내려가고, **틀리면** 0단계로 돌아가 바로 다음 퀴즈 맨 앞에 나옵니다. 되묻기 뒤에는 두 번 다 거의였을 때만 거의이고, 한 번이라도 틀렸으면 틀림입니다.
- 되묻기 화면에서 `f`(맞았는데요)나 `/learn 퀴즈 맞음`으로 첫 답을 맞힘으로 바꾸면 처음부터 맞힌 것처럼 셉니다(힌트를 봤으면 단계 그대로).
- 복습 순서는 틀린 개념 → 퀴즈로 본 개념(오래 밀린 것부터) → 아직 퀴즈를 안 본 개념(최근 배운 것부터)입니다.

**오늘 복습은 하루 10문제까지**입니다. 복습할 개념이 있으면 프롬프트 아래 상태줄에 `학습 노트 · 오늘 복습 3개 · /learn 복습`이 뜹니다.
그날 채점한 문제만큼 줄고, 10문제를 채점하면 상태줄이 내려가며 퀴즈 끝 줄에 `오늘 복습을 마쳤습니다 · 남은 개념은 내일 나옵니다`가 나옵니다. 직접 해 보기는 이 10문제에 세지 않습니다. 상태줄은 설정 `reviewReminder`로 끕니다.

**졸업**: 마지막 단계(60일)에서 때가 되어 또 답을 직접 적어 맞히면 아는 개념이 됩니다. 퀴즈 끝에 `졸업: 구조 분해 할당`이 나옵니다.

### 개념 모음과 학습 기록

- 노트의 "배울 개념"을 프로젝트를 넘어 모읍니다. 개념 모음(`3`) 맨 위에 `배운 개념 12개 · 최근 7일 새로 3 · 연속 3일째 · 퀴즈 4/6`이 한 줄로 나옵니다. 저장소에 팀 용어가 있으면 그 아래에 `팀 용어 12개 중 5개 만남 · 4에서 s`와 흐린 `아직: 캐시 키 · 페이지네이션 커서 외 5개`가 붙습니다.
- 개념마다 만난 횟수, 복습 상태, 최근에 만난 때, 마지막 퀴즈, 최근 설명, 그 개념이 나온 노트(누르면 그 노트로)가 있습니다. 줄은 `×2 · 다음 복습 3일 뒤 · 최근 10-08`처럼 만난 횟수 바로 뒤에 복습 상태가 옵니다(`퀴즈 틀림` · `아직 떠올려 본 적 없음`). 팀 용어로 들어온 개념은 만난 횟수 바로 뒤에 흐리게 `· 팀 용어`가 붙어(`가드 절 ×1 · 팀 용어 · 다음 복습 오늘 · …`) 좁은 패널에서도 보입니다.
- 그 위의 `복습할 개념 n개`에 틀린 것부터 다섯 개가 보이고, 오늘 몫이 남았으면 `q로 복습`을 안내합니다. 노트 아래에는 그 노트에서 `새로 배운 개념`과 `다시 만난 개념 for...of 반복문 ×2`가 나뉘어 나옵니다.
- 이미 배운 개념 이름을 모델에 알려 주므로 같은 개념은 같은 이름으로 쌓입니다. "구조 분해 할당 (Destructuring)"과 "구조 분해 할당"처럼 표기만 다른 이름은 한 개념으로 셉니다. 그래도 갈라졌으면 `/learn 합치기 A = B`로 합칩니다.
- **아는 개념**: `/learn 안다 const 선언, 화살표 함수`처럼 쉼표로 여럿 표시하고, `/learn 모른다 const 선언`으로 되돌립니다. 졸업한 개념도 아는 개념이 됩니다. 아는 개념은 오늘 복습 수 · 퀴즈 · 개념 목록에서 빠지고, 개념 모음 맨 아래 `아는 개념 12개 · …` 한 줄로 접힙니다. 다음 노트부터는 그 개념을 다시 가르치지 않고, 퀴즈로 3단계 이상 익힌 개념은 노트에서 `(복습)` 한 줄로만 짚습니다.
- **연속 학습일**: 노트가 쓰였거나 퀴즈·직접 해 보기를 채점한 날을 셉니다. 날짜별 기록은 최근 120일을 모든 프로젝트 합산으로 남깁니다.
- **`/learn 기록`**: 연속 학습일, 최근 7일(노트 · 새 개념 · 다시 만난 개념 · 퀴즈), 최근 30일 정답률(직접 해 보기 포함), 복습할 개념(`클로저 (퀴즈 틀림 10-12)`처럼, 오늘 틀렸으면 `(퀴즈 틀림 오늘)`)과 오늘 몫, `최근 7일 노트: 토 1 · 금 0 · …` 한 줄, 이 저장소 팀 용어 줄, 배운 개념 목록(많이 만난 순 20개), 아는 개념 한 줄, 학습 노트의 모델 호출 수를 한 번에 보여 줍니다.

## 노트 복사해 멘토에게 묻기 (`c` · `/learn 공유`)

막혔을 때 화면을 캡처하는 대신 노트 글을 복사해 멘토에게 묻습니다. 모델은 부르지 않습니다.

- 노트 아래 `이 노트로` 줄의 흐린 `c: 복사`를 누르면 토스트가 뜹니다: `노트를 복사했습니다 · 요청과 질문은 빼고 비밀값은 가렸습니다 · 붙이기 전에 읽어 보세요`.
- 대화 입력칸의 `/learn 공유`(`share`)는 패널에서 고른 노트(없으면 마지막 노트)를 같은 글로 복사하고 `노트를 클립보드에 복사했습니다 · 붙이기 전에 한 번 읽어 보세요`로 답합니다. 1.6까지의 `/learn 마지막`(`last`)도 같은 일을 합니다. 아직 쓰이지 않은 노트는 `이 노트는 아직 복사할 글이 없습니다 · (까닭)`으로 답합니다.

복사되는 글은 `**[학습 노트] 한 줄 요약**`, `10-13 · 파일 2개 · 개념: async/await · try/catch` 한 줄, **무엇이 바뀌었나**(전·후·예) · **왜 이렇게 바꿨을까** · **배울 개념** · **직접 해 보기**(할 일과 확인), 뺀 파일 줄, 그리고 끝의 빈칸 `**묻고 싶은 것**: `입니다. 빈칸을 채워 보내면 질문이 또렷해집니다.

- **넣지 않는 것**: 요청 문장, 노트 아래 질문과 답, diff와 코드 블록, 직접 해 보기의 고칠 줄과 예시 답, 이 컴퓨터의 경로. 비밀값은 `«가림»`으로 가립니다.
- **경로는 이렇게 바꿉니다**: 프로젝트 안은 `src/api/fetcher.ts` 같은 상대 경로로, 프로젝트 밖은 파일 이름만, 홈 폴더는 `~`로. Windows의 `C:\Users\…`, Git Bash의 `/c/Users/…`, WSL의 `/mnt/c/Users/…`, `\\wsl$\…` 같은 네트워크 공유(그 안의 프로젝트도 상대 경로), `\\?\C:\…` 같은 Windows 긴 경로도 그렇게 바꿉니다. 따옴표나 백틱으로 감싼 경로는 공백이 든 폴더 이름까지 지웁니다.
- **남는 것**: 배울 개념의 한 줄 코드 인용(백틱)과, 노트 본문이 적은 파일 이름이나 상대 경로는 남습니다. 프로젝트 밖 경로를 따옴표 없이 적었고 폴더 이름에 공백이 있으면 공백 뒤 폴더 이름이 남을 수 있습니다(예: `E:\고객사\빅뱅크 차세대\src\a.ts` → `빅뱅크 차세대\src\a.ts`). 붙이기 전에 한 번 읽어 보세요.
- 복사할 수 없는 곳에서는 같은 글을 대화창에 **흐린 줄**로 남깁니다. 이 줄은 Claude에게 가지 않습니다. 첫 줄은 휴대폰(Remote Control)에서 `복사할 수 없어 여기에 적습니다 · 길게 눌러 복사하세요`, 터미널·데스크톱·VS Code·클라우드 세션에서 `복사할 수 없어 여기에 적습니다 · 마우스로 끌어 골라 복사하세요`입니다. `/learn 공유`가 흐린 줄로 남겼으면 답은 `복사할 수 없어 노트를 흐린 줄로 적었습니다 · 그 줄은 Claude에게 가지 않습니다`이고, 답만 보이는 곳(채팅 채널, `claude -p`)에서는 답에 글을 적습니다.

## 팀으로 쓰기

### 팀 규칙 파일 `.claude/learn-notes.md`

프로젝트 폴더의 `.claude/learn-notes.md`에 팀 규칙과 용어를 적어 저장소에 커밋하면, 팀원 모두의 노트가 그것을 따르고 용어는 [팀 용어 연습](#팀-용어-연습)이 됩니다.
파일은 Claude Code를 켠 폴더(`/cd`로 옮겼으면 옮긴 폴더) 아래에서 찾습니다. 저장소 맨 위에 두고, 팀원에게도 저장소 맨 위에서 Claude Code를 켜라고 알려 주세요.

```markdown
## 규칙
- API 호출은 src/lib/fetcher.ts의 fetcher로 감쌉니다
- 바뀌지 않는 값은 const로 선언합니다

## 용어
- **fetcher**: 우리 팀의 API 호출 함수입니다 · `src/lib/fetcher.ts:12-30`
- **캐시 키**: 응답을 캐시에 넣을 때 쓰는 이름입니다 · `src/lib/cache.ts`
- **페이지네이션 커서**: 다음 페이지를 가리키는 값입니다 · `docs/learn/pagination.md`
- **불변 바인딩**: const로 묶은 이름. 다시 대입할 수 없습니다

## 빼기
- legacy/**
- *.generated.ts
- `docs/old drafts/**` 공백이 든 경로는 백틱으로 감쌉니다
```

- **`## 규칙`**: 글머리표 한 줄이 규칙 하나입니다. 노트의 "왜 이렇게 바꿨을까"에 바뀐 코드와 직접 닿는 규칙이 있을 때만 `팀 규칙: …` 한 줄이 붙고, 규칙과 달라 보이면 `팀 규칙과 다를 수 있음: …`으로 단정하지 않고 적습니다. 노트 아래 질문(`i`, `/learn 질문`)도 규칙을 근거로 답합니다. 규칙 판정은 모델의 참고 의견이고 코드 리뷰를 대신하지 않습니다.
- **`## 용어`**: `- **이름**: 설명` 꼴로 씁니다. 배울 개념이 용어에 있으면 그 이름을 글자 그대로 써서, 팀원 모두의 개념 모음에 같은 이름으로 쌓입니다. **적은 순서가 곧 연습 순서**입니다. 설명 안에 백틱으로 저장소 경로를 적으면 그 코드로 묻습니다.
- **`## 빼기`**: 노트에 내용을 싣지 않을 경로 패턴입니다. 설정 `excludePaths`와 합쳐지고 쓰는 법도 같습니다([설정](#설정)). 한 줄에 하나 또는 쉼표로 나눠 쓰고, 패턴 뒤의 낱말은 설명으로 보고 건너뜁니다. `!`로 다시 넣는 패턴은 지원하지 않습니다.
- 영어 제목(`## Rules` · `## Terms`(`Glossary`) · `## Exclude`)도 됩니다. 이 세 제목 밖의 줄과 `<!-- 주석 -->`은 읽지 않습니다.
- 노트와 질문에는 규칙과 용어를 합쳐 앞 3,000자만 모델에 보냅니다. 용어 연습은 이 예산과 따로, 용어를 파일 순서대로 100개까지(설명은 600자까지) 읽습니다. 파일을 고치면 다음 턴부터 다시 읽습니다. 200KB를 넘거나 `permissions.deny`의 읽기 금지 규칙에 걸린 파일은 읽지 않습니다.
- 노트가 아직 없는 패널에는 용어가 있으면 `팀 용어 12개로 연습할 수 있습니다 · 4에서 s`가 흐리게 나옵니다(복습할 개념이 이미 퀴즈를 채우면 끝이 `/learn 퀴즈 팀`). 용어 없이 규칙·빼기만 있으면 `이 저장소의 팀 규칙 파일을 읽었습니다 (규칙 2 · 용어 0 · 빼기 3)`이, 제목을 못 찾으면 `… 읽은 것이 없습니다 · 제목을 ## 규칙 · ## 용어 · ## 빼기로 씁니다`가 나옵니다.

### 팀 용어 연습

리더가 이미 쓰는 `## 용어`가 그대로 온보딩 연습이 됩니다. 새 파일이나 새 보기, 추가 모델 호출은 없습니다. 퀴즈의 빈자리를 씁니다.

**경로 적는 법**: 설명 안에 저장소 맨 위 기준 경로를 백틱으로 적습니다.

- `` `src/lib/fetcher.ts:12-30` ``: 12~30줄. `-` 대신 `~`도 됩니다. `` `…:12` ``는 12줄 둘레(5줄 앞부터 16줄)입니다.
- `` `src/lib/cache.ts` ``: 줄을 빼면 용어 이름이 처음 나오는 줄 둘레 16줄. 이름이 코드에 없으면 설명만으로 묻습니다.
- `` `docs/learn/pagination.md` ``: 마크다운이면 **팀 노트**로 보고 그 글에 근거해 '왜'를 묻습니다(이름 둘레 40줄, 이름이 없으면 맨 위부터 40줄).
- 경로로 보는 것은 소스·스타일·설정·문서 파일 확장자이거나, 폴더가 있고 줄 범위가 붙은 것입니다. 절대 경로 · `~` · 드라이브 문자 · 네트워크 경로 · URL · `..`는 받지 않습니다. Windows 역슬래시(`src\lib\a.ts:3-9`)도 됩니다. 백틱이 여럿이면 폴더가 든 첫 경로를 씁니다.

**읽지 않는 파일**: 아래에 해당하면 그 용어는 설명만으로 묻습니다. 링크라면 링크가 가리키는 파일까지 봅니다.

- 저장소 밖의 파일, 200KB를 넘는 파일, 텍스트가 아닌 파일, `.git` · `.hg` · `.svn` 안
- 비밀·잠금·생성 파일, `excludePaths`와 `## 빼기`에 맞는 파일, `permissions.deny`의 읽기 금지 규칙에 걸린 파일
- 비밀번호가 코드 모양으로 들어 있는 설정 파일: `wp-config.php`(`wp-config-local.php` 등) · `settings.php` · `settings.local.php` · `dbconfig.php` · `appsettings*.json` · `local.settings.json` · `secrets.json` · `.htpasswd`. 팀 용어로 읽으면 팀원 모두의 퀴즈에 실리기 때문입니다. 이 가운데 `secrets.json` 말고는 노트의 바뀐 코드에 예전처럼 가린 뒤 실립니다. 노트에서도 빼려면 `excludePaths`나 `## 빼기`에 넣으세요.

읽은 코드는 퀴즈 한 번에 파일 3개까지, 용어마다 700자까지, 비밀값을 가린 뒤 퀴즈 호출(설정한 모델, 기본 haiku)에 싣습니다.

**팀원에게 보이는 것**

- 이 저장소를 처음 연 세션에 토스트가 한 번 뜹니다: `이 저장소의 팀 용어 12개로 연습할 수 있습니다 · /learn 퀴즈`(복습할 개념이 이미 퀴즈를 채우거나 풀던 퀴즈가 남았으면 끝이 `/learn 퀴즈 팀`). 처음 설치해 환영 토스트가 뜬 세션, 클라우드 세션, `claude -p`에서는 띄우지 않고, 키를 가져가지 않습니다.
- 개념 모음(`3`) 머리말 아래(`팀 용어 12개 중 5개 만남 · 4에서 s`)와 `/learn 기록` · `/learn 보고서`(`- 이 저장소 팀 용어: 12개 중 5개 만남 · 아직 7개 (/learn 퀴즈 팀)`)에 진행 줄이 붙습니다. 보고서에는 만난 용어 이름도 적습니다.
- 새 퀴즈에서 때가 된 개념(다시 도전 포함)이 3개보다 적으면 남는 자리를 아직 안 만난 팀 용어가 순서대로 채웁니다. 문제 제목은 `문제 2/3 · 팀 용어 · 예측`, 그 아래 흐리게 `팀 코드 (fetcher.ts 12~30줄)`(마크다운이면 `팀 노트 (…)`)입니다. 답 칸, Enter 채점, `h`, 되묻기, `f`는 다른 문제와 같습니다.
- 아직 안 만난 용어를 채점하면 피드백 아래에 `팀 용어를 개념 모음에 넣었습니다`가 붙습니다(완전히 틀렸으면 ` · 다음 퀴즈 맨 앞에 나옵니다`도). 맞혀도 틀려도 그 용어는 이제 만난 것으로 셉니다. 그다음부터는 보통 개념처럼 간격 반복으로 나오고, 이 저장소에서는 팀 코드를 붙여 묻습니다. 다시 도전이 된 팀 용어는 지난번과 다른 코드로 묻고, 그때는 `팀 코드 (…)` 표시를 붙이지 않습니다.
- **`/learn 퀴즈 팀`**(`팀 용어` · `팀 퀴즈` · `팀으로` · `team`도 됩니다)은 세 자리를 모두 팀 용어로 채운 새 퀴즈 `팀 용어 퀴즈`를 만듭니다. 아직 안 만난 용어가 먼저이고, 그다음 때가 된 팀 용어, 곧 때가 될 팀 용어입니다. 풀던 퀴즈가 있어도 새 퀴즈를 만듭니다.
  - 팀 용어가 없는 저장소: `이 저장소에는 팀 용어가 없습니다 · .claude/learn-notes.md의 ## 용어에 적습니다`
  - 용어가 모두 아는 개념이면: `이 저장소의 팀 용어는 모두 아는 개념이라 퀴즈에 낼 것이 없습니다. 되돌리려면 /learn 모른다 개념 이름.`
- `/learn 복습`, `q`, 상태줄은 그대로입니다. 아직 안 만난 팀 용어는 '때가 된' 개념이 아니므로, 복습할 것이 없으면 새 퀴즈를 만들지 않습니다.

![/learn 퀴즈 팀: 대화창의 '팀 용어 퀴즈 · 3문제'(팀 코드 cartStore.js 4~10줄 · 팀 노트 orders.md 1~12줄 · 다시 도전 문제)와 패널의 '문제 1/3 · 팀 용어 · 예측', 팀 코드 (cartStore.js 4~10줄)](docs/images/pane-team.png)

**좋은 노트를 팀 자료로**: 좋은 노트를 `c`로 복사해 `docs/learn/fetcher.md`처럼 저장소에 커밋하고(커밋은 사람이 직접 합니다), 팀 용어 설명에 그 경로를 적으면 팀 용어 연습이 그 글을 팀 노트로 써서 묻습니다(이름이 없으면 맨 위부터 40줄, 700자까지). learn-notes는 저장소 작업 트리에 파일을 쓰지 않습니다.

### 저장소에서 팀원에게 자동으로 켜기

저장소의 `.claude/settings.json`에 아래 두 키를 넣어 커밋하면, 그 저장소를 연 팀원에게 learn-notes가 따로 설치하지 않아도 켜집니다.
팀원이 그 폴더를 처음 열 때 나오는 **폴더 신뢰 창을 받아들인 뒤**부터 적용됩니다.

```json
{
  "extraKnownMarketplaces": {
    "learn-notes": {
      "source": { "source": "github", "repo": "Owen-YC/learn-notes" }
    }
  },
  "enabledPlugins": {
    "learn-notes@learn-notes": true
  }
}
```

- 끄고 싶은 팀원은 자기 `.claude/settings.local.json`에 `"enabledPlugins": { "learn-notes@learn-notes": false }`를 둡니다.
- 설정값(`level`·`model`·`excludePaths`·`dailyAutoNotes`)은 저장소 설정으로 정할 수 없습니다. Claude Code는 플러그인 설정(`pluginConfigs`)을 사용자 설정과 관리 설정에서만 읽습니다. 팀 규칙·용어·뺄 경로는 위의 팀 규칙 파일로 정하세요.

### 관리자: 조직 전체에 설치하고 기본값 잠그기

조직의 **관리 설정**(managed settings)에 같은 두 키를 넣으면 모든 사람에게 설치되고 켜집니다(개인이 끌 수 없음). 여기에 `pluginConfigs`를 더하면 설정값이 **잠깁니다**. 팀원의 `/config`에는 learn-notes 항목에 그 값이 보이지만 바꿀 수 없습니다. 관리 설정에 넣지 않은 항목은 각자 `/config`에서 고릅니다.

```json
{
  "extraKnownMarketplaces": {
    "learn-notes": {
      "source": { "source": "github", "repo": "Owen-YC/learn-notes" },
      "autoUpdate": true
    }
  },
  "enabledPlugins": {
    "learn-notes@learn-notes": true
  },
  "pluginConfigs": {
    "learn-notes@learn-notes": {
      "options": {
        "level": "beginner",
        "model": "haiku",
        "excludePaths": "legacy/**, *.generated.ts, fixtures/",
        "dailyAutoNotes": 40
      }
    }
  }
}
```

- 관리 설정을 나눠 주는 길은 셋입니다: claude.ai의 **조직 설정 > Claude Code > Managed settings**(Teams·Enterprise), MDM, 또는 시스템 폴더의 `managed-settings.json`(macOS `/Library/Application Support/ClaudeCode/`, Linux·WSL `/etc/claude-code/`, Windows `C:\Program Files\ClaudeCode\`). 이미 쓰는 관리 설정이 있으면 그 JSON에 위 키만 더합니다.
- `autoUpdate: true`를 두면 새 판이 나왔을 때 각자 업데이트하지 않아도 백그라운드에서 따라옵니다. 이미 열려 있던 1.7.0 이후의 창은 다른 창에서 새 판이 돌기 시작하면 `/reload-plugins`를 하라고 스스로 알립니다.
- `excludePaths`는 쉼표로 구분한 한 줄 문자열로, `dailyAutoNotes`는 숫자로 씁니다. `model`은 `haiku`나 `sonnet`만 받습니다.
- 클라우드 세션(claude.ai 웹·앱의 Claude Code)에는 claude.ai 콘솔의 관리 설정만 닿습니다. 자세한 규칙은 공식 문서 [조직의 플러그인](https://code.claude.com/docs/en/plugins/org)과 [관리 설정](https://code.claude.com/docs/en/managed-settings)에 있습니다.

### 담당자용: `/learn 진단`

회사 전체에 깔면 "노트가 안 떠요" 같은 문의가 담당자에게 모입니다. 그때는 먼저 **`/learn 진단`**(`doctor`)을 복사해 보내 달라고 하세요.
대화 입력칸에 `/learn 진단`을 치면 **모델을 부르지 않고** 15줄 남짓한 진단을 만들어 클립보드에 복사하고, 대화창에도 그대로 적습니다.
첫 두 줄은 `진단 내용을 클립보드에 복사했습니다 · 팀 채널이나 담당자에게 그대로 붙여 주세요`와 `코드 · 요청 · 파일 이름 · 경로 · 개념 이름은 들어 있지 않습니다`입니다. 복사할 수 없는 곳(원격 제어·채팅 채널·클라우드 세션)이나 복사에 실패했을 때는 첫 줄이 `이 화면에서는 클립보드에 복사할 수 없어 여기에 적습니다`입니다.

```
learn-notes 진단 · 2026-10-16 10:12
- 버전: learn-notes 1.7.1 · Claude Code 2.1.302
- 다른 창: 1.7.1 (3분 전)
- 화면: terminal · 패널 오른쪽 56칸 · 터미널 132칸 · 키는 대화에 · Windows Terminal
- 설정: 자동 노트 켬 · haiku(관리자 잠금) · 하루 한도 40(관리자 잠금) · 일지 켬(기본 폴더) · 패널 자동 열기 켬 · 설명 수준 beginner
- 오늘: 노트 6개 · 모델 호출 9번 · 실패 1번
- 저장소: 1.4MB / 4MB (history 1.1MB · quizBank 190KB · concepts 96KB)
- 일지: 아직 못 쓴 노트 2개
- 최근 7일 문제 2건 (최근 것부터)
  - 10-16 09:58 노트 쓰기 · 서버 붐빔(529) · 다시 써서 됨
  - 10-15 17:20 일지 저장 · 쓸 권한 없음(EPERM) ×2
- 패널 초점(최근 7일): 초점 거절 ×3 · 마지막 10-16 09:40
```

| 줄 | 읽는 법 |
| --- | --- |
| 버전 · 다른 창 | 이 창의 learn-notes와 Claude Code 판, 하루 안에 쓰인 다른 창의 판(최근 3개). 저장소가 더 새 구조면 ` · 저장소가 새 구조(4, 이 창 3)라 개념 모음과 복습 단계를 고치지 않음`이 붙습니다 |
| 화면 | 그리는 화면, 패널 자리와 칸 수(`패널 닫힘` · `패널 자리 없음`), 터미널 칸 수와 전체 화면 여부, 키가 패널에 있는지, 터미널 프로그램(Windows Terminal · tmux · VS Code 등) |
| 설정 | 지금 설정값. 관리자가 잠근 항목에 `(관리자 잠금)`. 일지 폴더는 기본 · 바꾼 폴더 · 네트워크 폴더와, 폴더가 없으면 `아직 없음` |
| 오늘 · 저장소 · 일지 | 오늘 노트·호출·실패 수(패널 초점 거절은 빼고 셈), 플러그인 저장소 크기와 큰 키 3개, 일지에 아직 못 쓴 노트 수 |
| 최근 7일 문제 | 어디서 무엇이 실패했는지 분류 코드로 8줄까지: 노트 쓰기 · 일지 저장 · 저장소 · 퀴즈 만들기 · 채점 · 클립보드 복사 · 훅 등. 같은 일이 그 뒤 되면 `· 다시 써서 됨`(노트·일지) 또는 `· 그 뒤 됨` |
| 패널 초점 | 패널이 키를 갖지 않을 때 엔진이 초점 옮기기를 거절한 수. 실패가 아니라 따로 셉니다 |

흔한 원인: `쓸 권한 없음(EACCES/EPERM)`은 Windows의 '제어된 폴더 액세스'나 보안 프로그램, `네트워크 위치`는 `saveDir`가 공유 폴더, `서버 붐빔(529)` · `서버 오류(5xx)` · `연결 끊김`은 잠깐 오류(자동 노트는 30초 뒤 한 번 더 씀), `요청 한도` · `로그인 필요` · `결제 문제` · `모델 없음`은 계정 쪽 문제입니다.
진단은 최근 7일만, 분류 코드로만 남습니다(오류 원문과 경로는 남기지 않음). 진단 글은 대화창에도 적히므로 대화 맥락에 약 400토큰이 더해집니다.

### 권하는 도입 순서

1. 관리자 한 사람이 먼저 설치해 하루이틀 써 봅니다. `/learn 기록` 맨 아래의 모델 호출 수로 하루 사용량을 가늠합니다.
2. 저장소에 `.claude/learn-notes.md`(팀 규칙·용어·뺄 경로)와 `.claude/settings.json`(마켓플레이스와 `enabledPlugins`)을 커밋합니다. 규칙은 몇 줄로 시작하고, 신입이 먼저 익힐 용어를 순서대로 `## 용어`에 적습니다. 용어마다 대표 코드의 경로와 줄 범위를 붙이면 그 코드로 연습합니다.
3. 조직 전체에 쓰거나 값을 잠가야 하면 관리 설정으로 `model`(haiku), `excludePaths`, `dailyAutoNotes`를 정합니다.
4. 팀에 [소개 글](#팀에-공유하기)과 안내서 PDF를 보냅니다. 입문자에게는 "숫자 키는 한/영 상관없이, 글자 키는 영문 상태에서"와 "막히면 `/learn 진단`을 복사해 보내 주세요"를 꼭 알려 주세요.
5. 1~2주 뒤 회고나 1:1에서 각자 `/learn 보고서`를 붙여 이야기 거리로 씁니다. 줄 세우기나 평가에는 쓰지 않습니다. 사용량을 보고 `dailyAutoNotes`를 조정합니다.

## /learn 명령

한글 명령이 기본이고, 괄호 안의 영어 이름과 다른 말도 됩니다. `/learn 도움말`의 첫 줄에 설치된 판(`learn-notes 1.7.1 명령`)이 나옵니다.

| 명령 | 하는 일 |
| --- | --- |
| `/learn` | 학습 노트 패널 열기. 키는 대화 입력칸에 둡니다(패널로는 터미널은 `ctrl+x tab`·클릭, 데스크톱 앱은 클릭). 데스크톱 앱이 패널을 조금 늦게 붙이면 1.5초까지 기다렸다가 답하고, 그래도 아직이면 `학습 노트 패널을 여는 중입니다 · 잠시 뒤 오른쪽에 뜹니다. 뜨지 않으면 /learn을 한 번 더 칩니다.`와 마지막 노트를 적습니다. 패널을 띄울 수 없는 화면이면 마지막 노트를 대화창에 적습니다(직접 해 보기는 할 일과 확인만, `직접 해 보기: 패널에서 t로 고쳐 확인합니다`를 붙여서. 클라우드 세션에서는 `직접 해 보기: 데스크톱 앱에서 이 세션을 열면 패널에서 t로 고쳐 확인합니다`) |
| `/learn 복습` (`review`) | 오늘 복습을 바로 시작: 패널을 퀴즈로 열고 커서를 `내 답` 칸에 둡니다. 풀던 퀴즈가 있으면 그 문제, 없으면 새 퀴즈. 복습할 개념이 없거나 오늘 몫을 마쳤으면 새 퀴즈를 만들지 않습니다. 패널을 띄울 수 없는 화면이나 클라우드 세션, 원격 제어·채팅 채널에서는 문제를 대화창에 냅니다 |
| `/learn 퀴즈` (`quiz` · `문제`) | 대화창에서 풀기. 풀던 퀴즈가 있으면 다시 보여 줍니다(호출 없음, 한 번 더를 기다리는 문제는 내 첫 답과 되묻기도). 없으면 복습할 개념으로 새 퀴즈 |
| `/learn 퀴즈 1 내 답` | 1번 답을 Claude에게 채점받기. 첫 답이 거의·틀림이면 `1번 △ 아직입니다 · …` · `되묻기: …` · `한 번 더: /learn 퀴즈 1 새 답 · 정답: /learn 퀴즈 정답 1` 세 줄로 답합니다. 번호 없이 답만 적으면 아직 안 푼 첫 문제로 채점합니다(`1번 답으로 채점했습니다`). 답이 명령 낱말(`정답`·`힌트`·`맞`·`틀`·`채점`·`팀` 등)로 시작하거나 `내 답`·`새 답`을 그대로 보냈거나 한 글자면 채점하지 않고 쓰는 법을 알려 줍니다 |
| `/learn 퀴즈 새로` (`새` · `new`) | 풀던 문제가 있어도 새 퀴즈 받기. 한 번 더를 기다리던 문제는 첫 판정대로 매깁니다 |
| `/learn 퀴즈 팀` (`팀 용어` · `팀 퀴즈` · `team`) | 이 저장소의 팀 용어만으로 새 퀴즈 ([팀 용어 연습](#팀-용어-연습)) |
| `/learn 퀴즈 힌트` · `정답` | 지금 풀 문제 하나의 힌트(그 문제만 `힌트 봄`) · 정답. `힌트 2`(`2 힌트`) · `정답 3`처럼 번호를 붙입니다. 한 번 더를 기다리던 문제의 정답은 첫 판정대로 바로 매기고, 아니면 `맞음`·`틀림`으로 스스로 채점합니다 |
| `/learn 퀴즈 맞음 2` · `틀림 2` | 정답을 본 뒤 스스로 채점. 이미 채점한 문제의 채점도 바꿉니다(복습 단계도 함께). 한 번 더를 기다리는 문제에서는 첫 답을 그렇게 매깁니다 |
| `/learn 정리` (`recap` · `요약`) | 오늘 배운 것 정리(한 일 · 핵심 개념 · 헷갈리기 쉬운 것 · 다음에 해 볼 것). `어제` · `이번주` · `최근 7일` · `2026-10-03`도 됩니다. 정리는 일지에 남습니다 |
| `/learn 질문 …` (`ask` · `묻기`) | 패널에서 고른 노트(없으면 마지막 노트)에 대해 묻기. 답은 패널의 노트 아래와 일지에도 남습니다 |
| `/learn 기록` (`stats` · `concepts` · `개념` · `통계`) | 연속 학습일 · 최근 7일 · 정답률 · 복습할 개념 · 이 저장소 팀 용어 · 배운 개념 · 모델 호출 수 |
| `/learn 보고서` (`report` · `보고`) | 코드 없는 학습 보고서를 클립보드와 파일로 (기본 최근 7일) |
| `/learn 공유` (`share` · `마지막` · `last`) | 고른 노트를 요청·경로 없이 복사해 멘토에게 묻기. 패널의 `c`와 같습니다 |
| `/learn 진단` (`doctor`) | 막혔을 때 담당자에게 보낼 진단을 클립보드와 대화창에. 모델을 부르지 않습니다 |
| `/learn 찾기 말` (`find` · `검색`) | 모든 프로젝트의 노트에서 요청·내용·파일 이름·개념으로 찾기 |
| `/learn 일지` (`day`) | 이 프로젝트의 오늘 노트 목차. `어제` · `10-03` · `2026-10-03`도 되고, `/learn 일지 목록`은 일지가 있는 날짜 |
| `/learn 합치기 A = B` (`merge`) | 이름만 다른 같은 개념 합치기(A를 B로). 거꾸로(`B = A`) 하면 되돌립니다 |
| `/learn 안다 이름` (`know`) · `/learn 모른다 이름` (`unknow`) | 아는 개념으로 표시해 복습·퀴즈에서 빼기 · 되돌리기. 쉼표로 여럿 |
| `/learn 안키` (`anki`) | 퀴즈 문제와 개념을 Anki 카드 파일로 |
| `/learn 비우기` (`clear`) | 이 프로젝트의 노트를 패널에서 비우기. 먼저 노트 수를 알려 주고, `/learn 비우기 확인`이어야 비웁니다(일지 파일과 개념 모음은 그대로). 30초 다시 쓰기를 기다리던 노트는 다시 쓰지 않고 실패 노트로 일지에 남깁니다 |
| `/learn 도움말` (`help` · `도움`) | 명령과 패널 키 목록 |

도움말 본문에는 자주 쓰는 명령이 있고, `/learn 찾기` · `일지` · `합치기` · `안다` · `모른다` · `안키` · `비우기` · `진단`은 맨 끝 '가끔' 줄에 모여 있습니다.
1.5까지 쓰던 `/learn days`(`날짜`)는 `/learn 일지 목록`과 같은 답을 냅니다. `/learn save`(`저장`)는 `노트는 저절로 저장됩니다.`와 자주 쓰는 명령 목록으로 답합니다.
모르는 하위 명령을 치면 `자주 쓰는 것: /learn 패널 · /learn 복습 · /learn 퀴즈 · /learn 정리 · /learn 질문 … · /learn 기록 · 전체는 /learn 도움말`로 답합니다.

## 설정

`/config`의 learn-notes 항목에서 바꿉니다. 바꾸면 모드가 다시 불려 바로 적용됩니다. 터미널에서는 `claude plugin configure learn-notes@learn-notes`.
조직 관리자가 잠근 항목은 `/config`에 보이지만 바꿀 수 없습니다([관리자](#관리자-조직-전체에-설치하고-기본값-잠그기) 참고).

| 항목 | 기본값 | 설명 |
| --- | --- | --- |
| `autoNote` | 켜짐 | 끄면 바뀐 코드만 모으고 노트는 패널에서 `w`로만 씁니다 (그만큼 모델 비용이 들지 않습니다) |
| `model` | `haiku` | `haiku` · `sonnet`. 노트·퀴즈·채점·직접 해 보기 확인·질문·정리에 씁니다. haiku가 가장 싸고 빠릅니다 |
| `level` | `beginner` | `beginner`(용어를 쉬운 말로) · `intermediate`(개념 위주) · `advanced`(설계·트레이드오프) |
| `autoOpen` | 켜짐 | 첫 노트가 생기면 세션마다 한 번, 전체 화면 터미널의 대화 오른쪽에 패널을 엽니다(키는 가져가지 않음). 터미널이 144칸 이상일 때 열고, `/learn`으로 연 적이 있으면 110칸부터 엽니다(손으로 `ctrl+x x`로 닫으면 다시 144칸부터). 그보다 좁으면 알림만 띄웁니다 |
| `autoSave` | 켜짐 | 날짜별 마크다운 일지에 노트를 씁니다. 끄면 일지·`concepts.md`·정리·질문·직접 해 보기·보고서 파일을 모두 쓰지 않습니다(패널과 지난 노트에는 남습니다) |
| `reviewReminder` | 켜짐 | 복습할 개념이 생기면 프롬프트 아래에 오늘 복습할 개수를 띄웁니다 (하루 10개까지) |
| `saveDir` | (비움) | 비우면 `~/.claude/learning-notes`. `~`로 시작하면 홈 폴더 기준. 네트워크 공유 폴더는 쓰지 못할 수 있습니다 |
| `excludePaths` | (비움) | 노트에서 뺄 파일. 쉼표로 구분한 경로 패턴입니다. 예: `legacy/**, *.generated.ts`. 맞는 파일은 `(설정으로 뺀 파일)`로 이름만 남습니다. 팀 용어 연습도 이 파일은 읽지 않습니다 |
| `dailyAutoNotes` | `0` | 하루 자동 노트 최대 개수. 0이면 제한이 없습니다. 한도에 닿으면 그날은 턴이 끝나도 노트를 쓰지 않고, 패널에서 `w`를 누를 때만 씁니다 |

`excludePaths`(와 팀 규칙 파일의 `## 빼기`) 패턴은 `.gitignore`처럼 읽습니다.

- `/`가 없는 패턴은 아무 깊이의 파일이나 폴더 이름과 맞습니다. `*.generated.ts`, `fixtures`(그 폴더 아래 전부).
- `/`가 있는 패턴은 프로젝트 맨 위부터 그 경로와 그 아래 전부입니다. `legacy/**`, `src/gen`.
- 끝의 `/`는 폴더만(`fixtures/`), 앞의 `/`는 프로젝트 맨 위만(`/scripts`) 뜻합니다.
- `**`는 아무 경로, `*`는 이름 한 칸 안, `?`는 한 글자입니다. 대소문자는 가리지 않습니다.

계정 사용 한도에 양보하는 문턱(5시간 창 90% · 7일 창 95%)과 잠깐 오류의 다시 쓰기(30초 뒤 한 번)는 설정이 아니라 고정값입니다.
1.5.x에서 `model`을 `opus`로 골랐다면, 이제 선택지에 없어 기본값 `haiku`로 돌아갑니다.

## 노트가 안 생겨요

**먼저 `/learn 진단`을 담당자에게 붙여 보내 주세요.** 모델을 부르지 않고 진단을 만들어 클립보드에 복사합니다. 코드·요청·파일 이름·경로·개념 이름은 들어 있지 않습니다([담당자용: /learn 진단](#담당자용-learn-진단)).
그다음 하나씩 확인해 보세요.

1. **그 턴에 파일이 바뀌었나요?** 질문에 답만 한 턴은 노트가 없습니다. Claude가 파일을 만들거나 고친 턴에만 생깁니다.
2. **패널이 열려 있나요?** `/learn`으로 엽니다. 터미널에서 대화 오른쪽에 붙으려면 `/tui fullscreen`(전체 화면)이어야 하고, 아니면 프롬프트 위에 열립니다. 데스크톱 앱은 오른쪽에 `학습 노트`로 붙습니다(조금 늦게 붙으면 대화창에 `학습 노트 패널을 여는 중입니다 · 잠시 뒤 오른쪽에 뜹니다…`가 먼저 나옵니다).
   VS Code 확장에는 패널이 없습니다(`/learn`의 답: `패널을 그리는 화면이 아직 붙지 않아 마지막 노트를 여기에 적습니다. … VS Code 확장처럼 패널을 그리지 않는 화면이면 같은 폴더의 터미널에서 claude를 켜거나 데스크톱 앱에서 이 폴더를 연 뒤 /learn을 칩니다.`). VS Code 아래 터미널에서 `claude`를 켜도 됩니다. PowerShell에 바로 `/learn`을 치면 안 되고, `claude`를 켠 뒤 그 안에서 칩니다.
   클라우드 세션(웹 · 휴대폰에서 연 클라우드의 Claude Code)은 노트가 클라우드 컴퓨터에 쌓여 내 컴퓨터의 `/learn`에는 나오지 않습니다. 패널이 없으면 `/learn`이 마지막 노트를 대화창에 적고, `/learn 복습` · `/learn 퀴즈 1 내 답` · `/learn 질문`으로 대화창에서 배웁니다. 데스크톱 앱에서 연 클라우드 세션은 패널이 오른쪽에 붙을 수 있습니다.
   패널을 띄울 수 없는 화면(전체 화면이 아니고 패널이 열려 있지 않을 때, 데스크톱 앱이 패널을 붙이지 않은 클라우드 세션)에서는 노트가 준비되면 대화창에 흐린 줄 `학습 노트 · 한 줄 요약 · /learn으로 보기`가 남습니다. 이 줄은 Claude에게 보내지 않습니다. 패널을 닫았거나 다른 패널 뒤에 있으면 토스트로 알립니다.
3. **단축키가 안 먹나요?** `/learn`은 패널만 열고 키는 대화 입력칸에 둡니다. 패널을 클릭하거나 `ctrl+x tab`을 누르면 키가 패널로 갑니다.
   `ㅂ`·`ㅅ`·`ㅊ` 같은 글자가 대화 입력칸에 찍힌다면 한/영이 한글 상태입니다. 한글 상태에서는 `q`가 `ㅂ`, `t`가 `ㅅ`, `c`가 `ㅊ`으로 들어가 글자 단축키가 먹지 않습니다. 한/영 키로 영문 상태로 바꾸세요. 숫자 키(`1`~`4`)는 한/영 상관없이 눌립니다.
4. **설치한 폴더가 다른가요?** `/plugin`의 Installed 탭에 learn-notes가 있는지 보고, 없으면 빠른 시작의 두 줄을 다시 입력합니다.
5. **노트 칸이 노란 글씨인가요?** 기다리면 되는 경우가 많습니다.
   - `서버가 붐벼 30초 뒤 한 번 더 씁니다… · w로 바로 쓰기`: 서버 붐빔(529) · 서버 오류(5xx) · 연결 끊김 · 시간 초과(90초)로 자동 노트가 실패하면 30~35초 뒤 **한 번만** 저절로 다시 씁니다(앞말은 `서버 오류로` · `연결이 끊겨` · `시간이 너무 걸려`로 원인에 맞게 바뀝니다). 기다리지 않으려면 `w`. 다시 쓴 것도 실패하면 빨간 글씨가 남습니다. `w`로 직접 쓴 노트와 `claude -p`에서는 저절로 다시 쓰지 않습니다.
   - `Claude 사용 한도(5시간)를 90% 넘게 써서 자동 노트를 미뤘습니다 · w를 누르면 씁니다`: 구독 계정에서 5시간 창을 90% 넘게(또는 7일 창을 95% 넘게) 쓰면 메인 작업을 위해 자동 노트가 양보합니다. 토스트는 하루 한 번입니다. `w`로는 언제든 씁니다. API 키로 쓰는 세션에는 해당하지 않습니다.
   - `다시 불러온 뒤 이어서 씁니다…`(하늘색): `/reload-plugins`나 `/config` 변경 직후 쓰다 멈춘 노트(턴이 끝난 지 10분 안)는 저절로 이어 씁니다. 노트마다 한 번이고, 자동 노트로 세어 하루 한도를 따릅니다.
   - `노트를 쓰다 멈췄습니다 · w로 다시 쓰기`: 쓰는 도중에 멈춘 노트입니다. `w`로 씁니다.
6. **노트 칸이 빨간 글씨인가요?** `노트를 쓰지 못했습니다:` 뒤에 원인과 할 일이 적혀 있습니다.

   | 노트 칸의 글 | 뜻 |
   | --- | --- |
   | `서버가 붐빕니다 · w로 다시 쓰기`, `서버 오류입니다 (500) · w로 다시 쓰기`, `인터넷 연결을 확인하세요 · 연결되면 w로 다시 쓰기`, `시간이 너무 걸려 멈췄습니다 · w로 다시 쓰기` | 잠깐 오류(서버 붐빔 · 서버 오류 5xx · 연결 끊김 · 90초 시간 초과). 자동 노트면 30초 뒤 다시 쓴 것도 실패한 것입니다 |
   | `요청 한도에 걸렸습니다 · 잠시 뒤 w로 다시 쓰기` | 메인 세션과 나눠 쓰는 요청 한도. 한도를 더 깎지 않게 저절로 다시 쓰지 않습니다 |
   | `로그인이 필요합니다 (/login) · 로그인 뒤 w로 다시 쓰기` | `/login` 뒤 `w` |
   | `계정의 사용 한도나 결제 문제입니다 · 관리자에게 알려 주세요` | 계정·결제 쪽 문제 |
   | `이 계정에서 'sonnet' 모델을 쓸 수 없습니다 · /config에서 haiku를 골라 보세요` | 고른 모델을 이 계정에서 쓸 수 없음 |
   | `'sonnet' 모델을 부를 수 없습니다 · /config에서 다른 모델을 골라 보세요 · w로 다시 쓰기` | 조직 정책 등으로 모델을 부를 수 없음 |
   | `모델이 이 요청을 받지 않았습니다 · 계속되면 /learn 진단을 담당자에게 보내 주세요` | 요청이 거절됨 |
   | `중간에 끊겨 멈췄습니다 · w로 다시 쓰기` | 다시 불러오기로 끊겼는데 이어 쓰지 않은 노트(자동 노트 꺼짐·하루 한도 등). 일지에는 남습니다 |

   `w`로 **다시 쓰던** 노트가 다시 불러오기로 끊기면 실패로 바뀌지 않고 원래 노트로 돌아오며, 토스트 `다시 불러오는 사이 노트 다시 쓰기가 끊겼습니다 · 원래 노트는 그대로입니다 · w로 다시 쓰기`가 한 번 뜹니다. 세션이 끝나 남은 다시 쓰기도 다음 세션에 원래 노트로 보입니다.
7. **임시 폴더의 파일만 바뀌었나요?** 프로젝트 밖 임시 폴더의 파일은 Claude의 작업 파일로 보고 빼놓습니다(아래 "자세히").
8. **노트에서 빼는 파일만 바뀌었나요?** 비밀·잠금·생성 파일, `excludePaths`나 `## 빼기`에 맞는 파일, 읽기 금지 규칙에 걸린 파일만 바뀐 턴은 노트도 모델 호출도 없습니다([노트에 싣지 않는 파일](#노트에-싣지-않는-파일)).
9. **띄어쓰기·줄바꿈만 바뀌었나요?** JS·TS·CSS·SCSS·JSON·HTML·Vue·Svelte 파일에서 띄어쓰기와 줄바꿈만 바뀐 턴은 노트 칸에 `띄어쓰기·줄바꿈만 바뀌어 노트를 쓰지 않았습니다 · w로 쓰기`가 남습니다. Python·YAML은 들여쓰기가 뜻을 바꾸므로 늘 노트를 씁니다.
10. **하루 한도에 닿았나요?** `dailyAutoNotes`를 정했으면(관리자가 잠갔을 수도 있습니다) 한도를 넘은 턴에는 노란 글씨로 `오늘 자동 노트 한도(40개)에 닿았습니다 · w를 누르면 씁니다`가 남고, 그날 처음 한 번 토스트가 뜹니다. `w`로 쓰는 노트와 퀴즈·질문은 막지 않습니다.
11. **자동 노트가 꺼져 있나요?** `자동 노트가 꺼져 있습니다. w로 노트를 쓰거나 2로 전/후 코드를 보세요.`가 보이면 `/config`의 `autoNote`가 꺼진 것입니다.
12. **노트는 있는데 일지 파일이 안 생기나요?** 원인을 말하는 토스트가 원인마다 세션에 한 번 뜹니다. 못 쓴 노트는 다음 노트를 저장할 때 함께 씁니다.

    | 토스트 (`학습 노트를 파일에 쓰지 못했습니다: …`) | 할 일 |
    | --- | --- |
    | `디스크가 가득 찼습니다 · 다음 노트 때 다시 씁니다` | 디스크 공간을 비웁니다 |
    | `폴더에 쓸 권한이 없습니다(Windows의 '제어된 폴더 액세스'나 보안 프로그램이 막았을 수 있습니다) · 다음 노트 때 다시 씁니다` | 보안 프로그램에서 Claude Code를 허용하거나 `saveDir`를 다른 폴더로 |
    | `다른 프로그램이 파일을 잡고 있습니다 · 다음 노트 때 다시 씁니다` | 백신 검사·동기화 프로그램이 끝나기를 기다립니다 |
    | `읽기 전용 위치입니다 · /config의 saveDir를 쓸 수 있는 폴더로 바꿔 주세요` | `saveDir` 바꾸기 |
    | `저장 폴더가 없습니다 · /config의 saveDir를 확인해 주세요` | `saveDir` 확인 |
    | `네트워크 위치입니다 · /config의 saveDir를 내 컴퓨터 폴더로 바꿔 주세요` | `saveDir`를 내 컴퓨터 폴더로 |

    토스트 끝에는 늘 `· /learn 진단`이 붙습니다. 파일이 잡혀 있거나(EBUSY) 권한 오류(EPERM)면 0.5초 뒤 **조용히 한 번 더** 써 보고, 그래도 안 될 때만 토스트를 띄웁니다.
    문제가 남아 있으면 다음 세션을 시작할 때 하루 한 번 대화창에 흐린 줄이 남습니다(모델에 가지 않음): `learn-notes 점검: 일지에 아직 못 쓴 노트 3개 (폴더에 쓸 권한 없음) · /learn 진단`. 플러그인 저장소에 쓰지 못한 기록이 하루 안에 있었으면 `저장소에 쓰지 못한 기록이 있음 (…)`도 붙습니다.
    지난 노트 이력을 저장소에 쓰지 못하면 `학습 노트 이력을 저장하지 못했습니다: … · 다음 세션에 지난 노트가 빠질 수 있습니다 (일지 파일은 그대로) · /learn 진단`이 뜹니다.
13. **패널에 `패널을 그리지 못했습니다 · /learn 진단을 복사해 팀에 보내 주세요`가 보이나요?** 그 아래 줄대로 `대화창의 /learn 퀴즈 · /learn 기록은 그대로 됩니다`. `/learn` 명령이 `이 명령을 마치지 못했습니다 · /learn 진단으로 무엇이 막혔는지 볼 수 있습니다`로 답할 때도 `/learn 진단`을 보내 주세요.
14. **`learn-notes 새 버전(…)이 다른 창에서 쓰이고 있습니다` 알림이 떴나요?** 그 창에서 `/reload-plugins`를 실행합니다. 저장소가 이 창보다 새 구조면 [여러 창과 업데이트](#자세히)를 보세요.

## 비용과 개인정보

### 모델 호출

- 파일을 바꾼 턴마다 자동 노트로 모델 호출이 **한 번** 일어납니다(기본 haiku, 노트 하나에 바뀐 코드 최대 약 14,000자).
- 직접 하는 것은 할 때마다 한 번씩입니다: 퀴즈 받기 · 답 채점(되묻기 뒤 한 번 더 채점 포함) · 직접 해 보기 확인 · 질문 · 예시로 따라가기 · 더 쉽게 · 다시 쓰기 · 정리.
- 모델을 부르지 않는 것: `/learn 기록` · `보고서` · `진단` · `공유` · `찾기` · `일지` · `안키`, 패널의 `c`, `t`로 연습 펼치기, 풀던 퀴즈 다시 보기, 힌트, 정답 보기, 퀴즈의 `모르겠어요`, 직접 해 보기의 바꾼 곳 없음 · 한글 입력 · 예시 답과 같은 줄 · `모르겠어요`, 대화로 묻기의 학습 기록 도구.
- 모델을 부르지 않고 넘어가는 턴: 뺀 파일만 바뀐 턴, 띄어쓰기·줄바꿈만 바뀐 턴, 하루 한도(`dailyAutoNotes`)를 넘은 턴, 계정 사용 한도(5시간 창 90% · 7일 창 95%)를 넘은 턴.
- 호출은 지금 쓰는 Claude Code 계정으로 나갑니다. 메인 세션과 같은 계정의 요청 한도를 나눠 씁니다. 그래서 요청 한도에 걸린 노트는 저절로 다시 쓰지 않고, 사용 한도가 거의 찼으면 자동 노트가 먼저 양보합니다.
- `/learn 기록` 맨 아래에 사용량이 나옵니다: `학습 노트의 모델 호출: 오늘 12번 (자동 노트 9) · 최근 7일 61번 · 입력 약 18만 · 출력 약 3만 토큰`.
  입력에는 캐시로 읽고 쓴 토큰도 들어 있고, 응답이 온 호출은 오류여도 셉니다. 잠깐 오류 뒤 저절로 다시 쓴 호출은 호출 수에 들지만 자동 노트 수(하루 한도)에는 들지 않습니다. 재로드 뒤 이어 쓴 노트는 자동 노트로 셉니다. 금액은 계정마다 달라 적지 않습니다.

### 1.6.1과 비교한 호출

| 하는 일 | 1.6.1 | 1.7.0 |
| --- | --- | --- |
| 퀴즈 답 채점 | 답마다 1번 | 답마다 1번. 첫 답에 되묻기가 붙은 문제는 한 번 더 채점에 1번 더(문제당 최대 1번) |
| 퀴즈에서 `모르겠어요` | 채점 1번 | 0번 |
| 노트 아래 `t` | 이 노트 퀴즈: 문제 만들기 1번 + 문제마다 채점 | 직접 해 보기: 펼치기 0번, 확인 0~2번 |
| 잠깐 오류로 실패한 자동 노트 | 0번 (빨간 글씨, `w`를 눌러야 씀) | 30초 뒤 1번 |
| 재로드로 끊긴 노트 | 0번 | 10분 안이면 1번 (하루 한도 안). `w`로 다시 쓰던 노트는 0번(원래 노트로 돌아옴) |
| 계정 사용 한도 90%·95%를 넘은 턴 | 자동 노트 1번 | 0번 (`w`로는 씀) |
| 팀 용어 문제 · 오답 노트 · `c` · `/learn 공유` · `/learn 진단` | (없음) | 더 드는 호출 없음 |

예를 들어 하루 복습 10문제 가운데 첫 오답이 3~4개면 하루 3~4번 늘어납니다. `모르겠어요`를 자주 쓰거나 `t`(이 노트 퀴즈)를 쓰던 사람은 그만큼 줄어듭니다.
호출 수는 같고 입력·출력이 조금 느는 것도 있습니다: 채점 출력 한도 400 → 480토큰(되묻기 · 헷갈린 점 줄), 다시 도전 개념이 있는 퀴즈의 입력(개념마다 약 120토큰), 팀 용어 문제의 입력(용어마다 코드 700자와 설명 300자 이하, 퀴즈 한 번에 최대 약 3천 자), 자동 노트의 직접 해 보기 네 줄(노트마다 출력 약 20~40토큰).

기기 밖으로 나가는 것은 여전히 모델 호출뿐입니다. 클립보드 복사는 사람이 `c` · `/learn 공유` · `/learn 진단` · `/learn 보고서`를 칠 때만 하고, 복사 글은 어디에도 저장하지 않습니다. `/learn 진단`에는 코드, 요청, 파일 이름, 경로, 개념 이름, 오류 원문이 들어가지 않습니다.

### 노트에 싣지 않는 파일

아래 파일은 바뀌어도 **내용을 모으지 않습니다.** 모델 호출 · 일지 · 플러그인 저장소 어디에도 내용이 가지 않고, 이름과 까닭만 남습니다(노트 머리줄 아래의 `노트에서 뺀 파일 n개`, 전/후 보기 맨 아래, 일지의 `**뺀 파일**`, 노트마다 12개까지). 노트를 쓰는 모델에게는 그 파일의 값을 짐작하지 말고 이름으로만 말하라고 알립니다. 팀 용어 연습도 이 파일은 읽지 않습니다.

| 까닭 | 파일 |
| --- | --- |
| 비밀값이 들 수 있는 파일 | `.env`, `.env.local`처럼 `.env`로 시작하는 파일(`.env.example` · `.sample` · `.template` · `.dist`는 보통 코드로 다룸), `*.pem` · `*.key` · `*.p12` · `*.pfx`, `*.tfvars` · `*.tfvars.json` · `*.tfstate`, `id_rsa*` · `id_ed25519*` · `id_ecdsa*` · `id_dsa*`, `.npmrc` · `.pypirc` · `.netrc` · `.git-credentials`, 이름에 `credentials`가 든 `.json`, `service…account….json`, `secrets.*`, `~/.aws/credentials`, `.envrc` · `app.env` · `.env-prod`, `.pgpass`, `key.properties`, `*.jks` · `*.keystore` |
| 잠금·생성 파일 | `package-lock.json` · `npm-shrinkwrap.json` · `yarn.lock` · `pnpm-lock.yaml` · `bun.lock(b)` · `Cargo.lock` · `poetry.lock` · `Pipfile.lock` · `composer.lock` · `Gemfile.lock` · `go.sum`, `*.min.js` · `*.min.css` · `*.map`, 아무 깊이의 `node_modules/` · `__snapshots__/`, 프로젝트 맨 위의 `dist/` · `build/` · `out/` · `.next/` · `coverage/` · `.turbo/` · `.vercel/` |
| 설정으로 뺀 파일 | `excludePaths`와 팀 규칙 파일의 `## 빼기`에 맞는 파일 |
| 조직 설정으로 읽기가 막힌 파일 | 관리 설정이나 내 설정의 `permissions.deny`에 `Read(./config/prod.yml)`처럼 읽기가 막힌 파일 |

비밀 파일은 값이 그대로 들어 있을 수 있어서, 잠금·생성 파일은 사람이 쓴 코드가 아니라 배울 것이 없고 길어서 비용만 들기 때문에 뺍니다.

### «가림»으로 가리는 것

다른 파일의 바뀐 코드, 내 요청, Claude의 마지막 설명, 노트에 적은 질문 속 흔한 키 형식은 `«가림»`으로 바꿉니다. 변수 이름은 남기고 값만 바꿉니다.
모든 모델 호출 직전에 한 번 더 가리고(1.6.0 전에 저장된 노트·일지, 퀴즈에 적은 답, 직접 해 보기에 고친 줄, 팀 용어의 코드도), `/learn` 명령의 답, 복사 글, 학습 기록 도구가 대화로 주는 답, `/learn 안키` 파일과 `concepts.md`도 가립니다.
1.6.0 전에 저장된 노트에 비밀·잠금·생성 파일이나 뺄 경로의 파일이 들어 있으면, 그 노트가 밖으로 나갈 때 그 파일의 내용을 빼고 이름만 남깁니다.
노트 머리줄 아래의 `비밀값 n곳 가림`은 바뀐 코드에서 가린 곳만 셉니다.

| 가리는 것 | 예 |
| --- | --- |
| 서비스 키와 토큰 | Anthropic · OpenAI(`sk-ant-…`, `sk-proj-…`, 숫자가 든 `sk-…`), AWS 액세스 키 ID(`AKIA…`, `ASIA…`), GitHub(`ghp_…` · `gho_…` · `ghu_…` · `ghs_…` · `ghr_…` · `github_pat_…`), Slack(`xoxb-…` 등), Google(`AIza…`), Stripe(`sk_live_…` · `sk_test_…` · `rk_live_…`), GitLab(`glpat-…`), npm(`npm_…`), Hugging Face(`hf_…`), Supabase(`sb_secret_…`) |
| 봇 토큰 · 웹훅 주소 | Telegram · Discord 봇 토큰, Slack · Discord 웹훅 주소의 비밀 부분 (`hooks.slack.com/services/«가림»`) |
| 인증 헤더와 토큰 | JWT(`eyJ….….…`), `Bearer …`, `Authorization: Basic «가림»` (git 설정의 `http.extraheader`, `curl -H` 등. Basic은 1.7.0부터) |
| 개인 키 | `-----BEGIN … PRIVATE KEY-----`와 END 사이 본문 (BEGIN·END 줄은 남김), 잘려 나온 60자 이상의 base64 줄 |
| 접속 문자열의 비밀번호 | `postgres://user:«가림»@host`, `redis://:«가림»@host` (mysql · mongodb+srv 등 다른 scheme도) |
| 비밀을 뜻하는 이름에 준 따옴표 값 | `password: "«가림»"`, `api_key = '«가림»'`, `clientSecret: "«가림»"` (이름에 password · secret · token · api_key · access_key · private_key가 든 것) |
| 이름이 KEY로 끝나는 따옴표 값 | `WEATHER_KEY = "«가림»"`, `serviceKey: "«가림»"` (값이 키 모양일 때만: 숫자와 글자가 섞인 16자 이상, UUID 꼴. `storageKey = "theme"`은 그대로) |
| 이름이 PASS · PWD로 끝나는 따옴표 값 | `DB_PASS = "«가림»"`, `pass: "«가림»"` (글자만 있어도 가림. `renderPass: 'shadow'`처럼 낱말 이름은 그대로) |
| 대문자 dotenv 값 | `OPENAI_API_KEY=«가림»`, `DB_PASSWORD=«가림»`, `export AUTH_TOKEN=«가림»` |
| 설정 파일의 따옴표 없는 값 | `.properties` · `.ini` · `.cfg` · `.conf` · `.toml` · YAML에서 `password: «가림»`, `spring.datasource.password=«가림»`, `aws_secret_access_key = «가림»`, `apiKey: «가림»`, `mail.pass=«가림»` (`access_token: 3600` 같은 숫자, `password: Password` 같은 번역 라벨, `true` · 버전은 그대로) |

**못 가리는 것**도 있습니다. 흔한 형식만 잡기 때문입니다.

- 공백이 든 따옴표 값(`password: "correct horse battery"`), `config["password"] = "…"`처럼 이름이 따옴표 안에 든 것
- 코드 파일(`.js` · `.py` · `.php` 등) 안의 따옴표 없는 값, PHP의 `define('DB_PASSWORD', '…')`나 `'password' => '…'` 같은 꼴(설정 파일에서만 가립니다)
- 도구마다 다른 설정 형식: `.kube/config`의 `client-key-data`, `.docker/config.json`의 `auth`, Maven `settings.xml`의 `<password>` (이런 파일은 `excludePaths`에 넣으세요)
- 사내에서만 쓰는 토큰 형식, 이름으로 비밀임이 드러나지 않는 값
- 일부러 두는 것: `${DB_PASS}` · `$TOKEN` · `<your-key>` 같은 자리표시, `process.env.API_KEY`처럼 값이 아닌 것, `passwordLabel` · `tokenUrl`처럼 비밀에 "대한" 이름, `=====` 구분선, `package.json`의 의존성 버전, `show ? "password" : "text"` 같은 삼항식, 한글 값(`"password": "비밀번호"`), 설정 파일의 `true` · 버전 · 문장

가림은 늘 켜져 있고 끄는 설정은 없습니다. 사내 비밀 파일이 따로 있다면 `excludePaths`나 팀 규칙 파일의 `## 빼기`에 넣으세요.

### 알아 둘 것

- **메인 Claude 세션은 이미 그 내용을 봤습니다.** Claude가 그 파일을 읽고 고쳤기 때문입니다. 이 모드가 막는 것은 **노트를 쓰려고 한 번 더 나가는 모델 호출**과 **일지·플러그인 저장소에 남는 사본**입니다. 대화에 비밀값을 붙여 넣지 않는 습관이 먼저입니다.
- 1.6.0 전에 쓴 일지 파일과 저장된 노트 자체는 고치지 않습니다(나갈 때만 가림). 옛 일지가 걱정되면 일지 폴더(`~/.claude/learning-notes/`)의 파일을 직접 확인하세요.
- 노트·일지·개념 모음·학습 기록·퀴즈·오답 노트·보고서 파일은 모두 내 컴퓨터에만 저장됩니다. 다만 `/learn` 명령의 답(기록·진단·대화창에 적은 보고서 등)과 학습 기록 도구의 답은 대화창에 들어가 메인 Claude도 읽습니다. 복사하지 못해 흐린 줄로 남긴 노트 글, 세션 시작 점검 줄, 새 버전 알림 줄은 Claude에게 가지 않습니다.
- 팀 용어 퀴즈의 문제에 팀 코드가 실리면, 다른 퀴즈 문제처럼 플러그인 저장소의 퀴즈와 문제 모음(`/learn 안키`용)에 남습니다. 저장소에는 그 문제의 파일 이름과 줄 범위만 따로 적고, 읽은 코드 자체는 따로 두지 않습니다.

  - 다른 창이 먼저 첫 답을 한 문제에 답하면: `이 문제는 그사이 다른 창에서 먼저 답했습니다. 한 번 더 적어 보세요.` (그 창의 되묻기가 이 창에 보입니다)

  - 다른 창이 이미 매긴 연습에 Enter: `이 연습은 다른 창에서 이미 매겼습니다` (다시 매기지 않음). `a`를 누르면 알림 없이 그 창의 판정과 예시 답을 보여 줍니다.

- **저장 구조 가드**: 저장소의 구조 번호가 이 창보다 높으면(다음 판이 구조를 바꾼 경우) 이 창은 다시 불러올 때까지 개념 모음 · 아는 개념 · 복습 단계 · 합치기 · 문제 모음 · 오답 노트 · 팀 용어 표시를 고치지 않습니다. 노트와 일지, 퀴즈는 그대로 씁니다. 알림 끝에 `· 다시 불러올 때까지 이 창은 개념 모음과 복습 단계를 고치지 않습니다(노트와 일지는 그대로)`가 붙고, 그동안 `/learn 안다`·`모른다`·`합치기`는 `/reload-plugins`로 바꾸고, 계속되면 `/learn 진단`을 보내라고 답합니다.

- 읽기 금지 규칙: `permissions.deny`의 `Read` 규칙(관리 설정 포함)을 Claude Code에 물어 따릅니다. PreToolUse 훅이나 자동 분류기로 막는 규칙은 반영하지 않습니다. 판정을 받지 못하면 허용으로 봅니다.
- 학습 기록 도구(`mcp__learn-notes__notes`)는 읽기 전용이고, 개념은 이름 · 만난 횟수 · 복습 상태만 줍니다. 권한 창 없이 허용하지만, deny 규칙과 설정 규칙·훅이 요구한 권한 창은 그대로 따릅니다.
- 팀 규칙 파일은 저장소 내용이므로 규칙과 용어를 3,000자로 잘라 프롬프트에 넣습니다. 링크로 커밋된 팀 파일은 링크가 가리키는 파일도 읽기 금지 규칙에 걸리지 않을 때만 읽습니다. 팀 용어의 코드도 저장소에 든 자료로 다루라고 모델에 알리고(그 안의 형식 지시나 실행 지시를 따르지 않음), `.git` · `.hg` · `.svn` 안과 비밀번호가 든 설정 파일(`wp-config.php` · `appsettings*.json` 등)은 읽지 않습니다.
- 실패 기록(`/learn 진단`)은 분류 코드만 남깁니다. 오류 원문과 경로는 debug 로그에도 남기지 않습니다.
- learn-notes의 훅이 실패하거나 시간을 넘겨도 사람의 프롬프트, 권한 판정, 도구 결과는 그대로 지나갑니다. 실패는 진단에 남고, `/learn`은 `이 명령을 마치지 못했습니다 · …`로, 패널은 두 줄 안내로 대신합니다.

</details>

## 팀에 공유하기

팀 메신저에 그대로 붙여 넣을 수 있는 소개 글입니다.

```text
안녕하세요! 바이브코딩하면서 공부도 같이 되도록 Claude Code 모드를 하나 만들었어요. 이름은 learn-notes예요 📒

🤔 모드(MOD)가 뭐예요?
Claude Code에 기능을 덧붙이는 확장 프로그램이에요. 크롬 확장 프로그램처럼 한 번 설치하면 Claude Code 안에 새 명령과 패널이 생겨요.

✨ learn-notes가 해 주는 것
• Claude가 코드를 고치면, 턴이 끝날 때 "무엇이 왜 바뀌었고 무엇을 배울 수 있는지"를 학습 노트로 정리해 오른쪽 패널에 보여 줘요
• 코드가 전에 하던 일과 이제 하는 일을 한 줄씩, 차이가 드러나는 예시와 함께 보여 줘요
• 바뀌기 전/후 코드를 나란히 놓고, 바뀐 줄과 바뀐 낱말까지 색으로 표시해 줘요
• 노트 끝의 "직접 해 보기"에서 내 코드 한 줄을 패널 안에서 고쳐 보고 바로 확인받아요 (파일은 안 바뀌어요)
• 노트 아래에서 바로 물어보고, 예시 하나로 코드를 따라가 보고, 더 쉬운 말로 다시 설명받을 수 있어요
• 배운 개념은 프로젝트가 달라도 계속 쌓이고, 잊을 때쯤 "내가 만든 코드"로 복습 퀴즈를 내요. 답을 적고 Enter를 누르면 Claude가 채점해 줘요
• 첫 답이 틀리면 정답 대신 되묻기가 먼저 나와서 한 번 더 떠올려 봐요. 그래도 헷갈린 점은 오답 노트에 남아 다음 퀴즈가 다른 코드로 다시 물어요
• 저장소의 .claude/learn-notes.md에 팀 용어를 적어 두면, 그 용어를 우리 팀 코드로 연습하는 퀴즈가 돼요 (/learn 퀴즈 팀)
• 막히면 c 한 번으로 요청·경로를 뺀 노트를 복사해 멘토에게 물어볼 수 있어요
• .env 같은 비밀 파일은 노트에 싣지 않고, 코드 속 흔한 키 형식은 «가림»으로 가려요
• /learn 보고서 로 코드 없는 학습 기록을 만들어 1:1이나 회고에 붙일 수 있어요

🛠 설치 (2분)
Claude Code v2.1.289 이상이 필요해요 (claude --version 으로 확인)
1) Claude Code 안에서 아래 두 줄 입력
   /plugin marketplace add Owen-YC/learn-notes
   /plugin install learn-notes@learn-notes
2) Claude Code를 다시 켜요. 터미널은 /tui fullscreen (전체 화면이어야 패널이 오른쪽에 붙어요), 데스크톱 앱은 그대로 돼요
3) /learn 으로 패널 열기 → 평소처럼 코딩을 요청하면 몇 초 뒤 노트가 떠요
4) /learn 도움말 첫 줄에 learn-notes 1.7.1 명령 이 나오면 성공!

💡 알아 두면 좋은 것
• 오늘 복습은 /learn 복습 한 번이면 돼요. 패널이 퀴즈로 열리고 바로 답을 적어 Enter
• 모르겠으면 "모르겠어요"라고 적고 Enter 하면 힌트(힌트가 없으면 정답)가 나와요. 정답 보기(a)는 한 번 적어 본 뒤에 나와요
• 패널의 키를 쓰려면 터미널은 ctrl+x tab (또는 패널 클릭), 데스크톱 앱은 패널 클릭, Esc 를 누르면 대화로 돌아가요
  1 노트 · 2 전/후 · 3 개념 모음 · 4 퀴즈 · q 오늘 복습
  노트 아래: t 직접 해 보기 · e 더 쉽게 · r 예시로 따라가기 · i 질문하기 · c 복사
• 숫자 키는 한/영 상관없이 돼요. 글자 키(q, t, e, r, i, c)는 영문 상태에서 눌러요 (한글 상태면 q가 ㅂ으로 들어가 안 먹어요)
• 퀴즈는 답을 적고 Enter만 누르면 다음 문제로 넘어가요
• Windows는 작업 폴더에서 켜 주세요: cd ~\practice 후 claude
  (관리자 PowerShell의 기본 위치인 System32에서 켜면 파일이 임시 폴더에 생겨요)
• 노트는 기본으로 가장 저렴한 haiku 모델이 써요. 설명 수준(초급/중급/고급), 자동 노트 끄기, 노트에서 뺄 파일은 /config 의 learn-notes 항목에서 바꿀 수 있어요
• 한글 명령도 돼요: /learn 복습 · 퀴즈 · 정리 · 질문 · 기록 · 보고서 · 공유 · 도움말
• 대화창에 "오늘 배운 거 알려 줘"라고 그냥 물어봐도 돼요
• 업데이트 뒤 "새 버전이 다른 창에서 쓰이고 있습니다" 알림이 뜨면 그 창에서 /reload-plugins 를 쳐 주세요

🆘 막히면
/learn 진단 을 치면 진단이 클립보드에 복사돼요. 코드·요청·파일 이름은 들어 있지 않으니 그대로 붙여서 보내 주세요

📎 자세한 설명
• 안내서 PDF (모드 개념부터 기능·활용 팁까지)
  https://github.com/Owen-YC/learn-notes/blob/main/docs/team/learn-notes-guide.pdf
• 소개 PPT (바로 내려받기)
  https://github.com/Owen-YC/learn-notes/raw/main/docs/team/learn-notes-intro.pptx
• 저장소·사용 데모 영상
  https://github.com/Owen-YC/learn-notes

써 보다가 이상한 게 보이면 /learn 진단 과 함께 편하게 보내 주세요. 이런 기능 있으면 좋겠다는 의견도 환영이에요 🙌
```

## 개발

```
.claude-plugin/plugin.json        매니페스트 · 설정 항목(userConfig)
.claude-plugin/marketplace.json   이 저장소를 마켓플레이스로 쓰게 하는 목록
hooks/hooks.json                  훅 모듈 위치
hooks/register.tsx                훅: 변경 수집 · 노트 작성과 다시 쓰기 · 패널(직접 해 보기 · 되묻기 퀴즈) · /learn · 학습 기록 도구 · 실패 기록 · 버전 도장
hooks/notes.ts                    순수 함수: diff 자르기·되읽기 · 비밀값 가림·뺄 파일 · 전/후와 바뀐 낱말 · 프롬프트 · 팀 규칙 파일과 팀 용어 · 직접 해 보기 · 오답 노트 · 복사 글 · 진단 · 일지 · 간격 반복 · 보고서 · Anki
types/index.d.ts                  $.state 계약
tests/*.test.ts                   claude plugin test로 도는 검사
docs/qa/점검표.md                  새 판을 내기 전 사람이 실제 터미널에서 눌러 보는 장면
```

- 검사: `claude plugin validate .` · `claude plugin test .`
- 고쳐 보며 쓰기: `claude --plugin-dir .`로 열면 파일을 고칠 때마다 대화 중에도 다시 불러옵니다. 이때 settings.json의 설정 이름은 `learn-notes@learn-notes`가 아니라 `learn-notes`(또는 `learn-notes@inline`)입니다.
- 타입 검사: `tsconfig.json`이 가리키는 `.claude-plugin/types/`(Claude Code가 모드 작업 폴더에 만들어 두는 타입 정의)가 있을 때 `npx tsc --noEmit -p .`
- 실제 터미널 점검: 자동 테스트가 보지 못하는 한글 입력기 · 초점 · 클립보드 · 터미널 폭은 [점검표](docs/qa/점검표.md)대로 눌러 봅니다.

버그나 제안은 [Issues](https://github.com/Owen-YC/learn-notes/issues)에 남겨 주세요. `/learn 진단`을 붙여 주시면 원인을 빨리 찾습니다.
