# learn-notes · 바이브코딩 학습 노트

Claude가 코드를 고치면 **바뀌기 전과 후**를 모아 두었다가, 턴이 끝날 때마다
"무엇이 왜 바뀌었고 무엇을 배울 수 있는지"를 **학습 노트**로 정리해 오른쪽 패널에 보여 주는
[Claude Code](https://code.claude.com) 모드(mod)입니다.
코드가 하던 일과 이제 하는 일을 **전/후 한 줄씩과 예시**로 보여 주고, 바뀐 줄에서는 **바뀐 낱말까지** 표시합니다.
노트에서 바로 묻거나 예시 하나로 코드를 따라가 보고, 배운 개념은 프로젝트를 넘어 쌓이며, 잊을 때쯤 **내가 만든 코드로** 복습 퀴즈를 냅니다.
답을 적고 Enter를 누르면 Claude가 채점합니다.
`.env` 같은 비밀 파일은 노트에 싣지 않고, 코드 속 흔한 키 형식은 `«가림»`으로 가립니다.

![learn-notes 사용 모습: /learn으로 패널을 열고, 코딩을 요청하면 실시간 변경 → 학습 노트(전·후·예) → 2 전/후(바뀐 낱말까지) → 3 개념 모음 → 노트에 질문 → 예시로 따라가기 → 더 쉽게 → /learn 복습: 내 코드로 낸 문제와 힌트 → Enter로 채점 → /learn 기록·보고서로 이어진다](docs/images/demo.gif)

<sub>사용 흐름을 약 1분으로 보여 주는 데모입니다. 장면마다 모드의 테스트 키트로 엔진이 실제로 그린 화면을 이어 붙였고, 노트·질문의 답·퀴즈·힌트·채점은 모두 이 모드의 프롬프트로 haiku가 실제로 쓴 글입니다.</sub>

> **English**: A Claude Code mod for learning while you vibe-code. Every turn in which Claude edits files,
> it collects the before/after diffs and has a small model (haiku by default) write a short study note:
> what the code did before and does now (with an example), why, concepts to learn, and what to try yourself.
> The before/after view marks changed lines and the very words that changed. Ask follow-up questions under a note,
> walk through the change on one example, and review with spaced-repetition quizzes built from your own code
> (predict the output, explain why, change it), graded by Claude. Secret, lock and generated files stay out of notes,
> and common key formats are masked before anything is sent to a model or saved. A code-free learning report
> and a team rules file help teams use it together. Notes are written in Korean.

## 빠른 시작

Claude Code **v2.1.289 이상**이 필요합니다 (`claude --version`).

1. Claude Code 안에서 두 줄을 입력해 설치합니다.

   ```
   /plugin marketplace add Owen-YC/learn-notes
   /plugin install learn-notes@learn-notes
   ```

2. Claude Code를 다시 시작하고 `/tui fullscreen`으로 전체 화면으로 바꿉니다. 패널이 대화 오른쪽에 붙으려면 전체 화면이어야 합니다.
3. `/learn`으로 패널을 엽니다. 키는 대화 입력칸에 그대로 있어서, 이어서 치는 글은 Claude에게 가는 요청이 됩니다.
   패널의 키를 쓰려면 `ctrl+x tab`을 누르거나 패널을 클릭합니다. 그러면 보기 줄 아래에 흐리게 `Esc: 대화로 돌아가기 · 글자 키는 영문 상태에서`가 보입니다(처음 설치해 노트도 개념도 없을 때는 패널에 안내 글만 있고, 첫 노트가 생기면 보기 줄이 나타납니다). `Esc`를 누르면 대화 입력칸으로 돌아갑니다(패널은 그대로 있습니다).
   **오늘 복습은 `/learn 복습`** 한 번이면 됩니다. 패널이 퀴즈로 열리고 커서가 `내 답` 칸에 있어서 바로 답을 적습니다.
4. 평소처럼 코딩을 요청합니다. 예: `hello.js에 이름을 받아 인사하는 함수를 만들어 줘`. Claude가 파일을 고친 턴이 끝나면 몇 초 안에 노트가 뜹니다.
5. 키를 누를 때:
   - **숫자 `1`~`4`는 한/영 상태와 상관없이** 눌립니다.
   - `q`·`t`·`e` 같은 **글자 키는 영문 상태**에서 누르세요. 한글 상태면 `q`가 `ㅂ`으로 들어가 단축키가 먹지 않습니다.
   - 대화로 갔다가 패널로 돌아올 때는 패널을 마우스로 클릭하거나 `ctrl+x tab`을 누릅니다.

`/learn 도움말`로 명령 목록이 나오면 제대로 켜진 것입니다. 처음 설치한 세션에서는 `learn-notes가 켜졌습니다 · 파일을 고치는 요청을 하면 노트가 생깁니다 · /learn으로 패널` 알림이 한 번 뜹니다.

- **업데이트**: `/plugin` → Installed → learn-notes → Update, 그다음 `/reload-plugins`. 터미널에서는 `claude plugin update learn-notes@learn-notes`. 열려 있던 다른 Claude Code 창에도 `/reload-plugins`를 실행하거나 다시 시작하세요(옛 버전이 계속 돌면 아는 개념 표시가 엇갈릴 수 있습니다).
- **지우기**: `claude plugin uninstall learn-notes@learn-notes` (일지 파일 `~/.claude/learning-notes/`는 남습니다)
- **설치 없이 한 번 써 보기**: 이 저장소를 받아 `claude --plugin-dir <저장소 경로>`로 시작합니다.
- **Windows**: PowerShell에서 `irm https://claude.ai/install.ps1 | iex`로 Claude Code를 설치한 뒤 위와 똑같이 씁니다.
  Claude Code는 **작업할 폴더에서** 켜세요(`cd ~\practice` 뒤 `claude`). 관리자 PowerShell처럼 `C:\Windows\System32`에서 켜면 Claude가 파일을 임시 폴더에 만듭니다.
  이때도 노트는 생기고, 패널 맨 위에 작업 폴더에서 켜라는 안내가 뜹니다. `claude`를 못 찾으면 새 창을 열거나 `$env:Path += ";$HOME\.local\bin"`을 입력하세요.
- **클라우드 세션**(claude.ai 웹·앱에서 여는 Claude Code 세션)에서는 패널이 보는 화면에 뜨지 않을 수 있습니다. 이때 노트가 준비되면 대화창에 흐린 줄(`학습 노트 · 한 줄 요약 · /learn으로 보기`)이 남고, `/learn`은 마지막 노트를 대화창에 적어 줍니다. 퀴즈·질문도 명령(`/learn 퀴즈 1 내 답`, `/learn 질문 …`)으로 다 됩니다.

## 하는 일

1. **모읍니다.** Claude가 `Edit`·`Write`, 또는 파일을 바꾸는 셸 명령(Bash, Windows에서는 PowerShell)을 쓸 때마다 바뀐 내용을 모읍니다. 턴이 도는 동안 패널 맨 위에 `● 작업 중: 파일 n개`가 보입니다.
   비밀값이 들 수 있는 파일(`.env` 등)과 잠금·생성 파일(`package-lock.json` 등)은 **이름만 남기고 내용은 모으지 않습니다.** 다른 파일 속 흔한 키 형식은 `«가림»`으로 바꿉니다.
2. **노트를 씁니다.** 턴이 끝나면 저렴한 모델(기본 `haiku`)이 바뀐 코드와 내 요청, Claude의 마지막 설명을 읽고
   다섯 칸짜리 노트를 씁니다: **한 줄 요약 · 무엇이 바뀌었나 · 왜 이렇게 바꿨을까 · 배울 개념 · 직접 확인해 볼 것**.
   "무엇이 바뀌었나"는 코드 설명 대신 **전**(하던 일) · **후**(이제 하는 일) · **예**(차이가 드러나는 입력과 결과) 세 줄로 씁니다.
3. **패널에서 봅니다.** 숫자 키 `1`~`4`로 노트, 바뀐 낱말까지 표시한 전/후, 지금까지 배운 개념, 퀴즈를 오갑니다. 지난 세션의 노트도 그대로 남아 있습니다.
4. **쌓습니다.** 노트는 날짜별 마크다운 일지(`~/.claude/learning-notes/`)에, 배운 개념은 프로젝트를 넘어 한 목록(`concepts.md`)에 쌓입니다.
5. **복습합니다.** 개념마다 다음 복습 날짜가 있어, 때가 되면 내가 만든 코드로 문제를 냅니다. 상태줄에 `오늘 복습 n개 · /learn 복습`이 보이면 `/learn 복습`으로 바로 시작합니다(패널에서는 `q`). 답을 적으면 Claude가 채점합니다.

## 패널 사용법

### 키 한눈에

| 키 | 하는 일 |
| --- | --- |
| `1` · `2` · `3` · `4` | 보기 바꾸기: 노트 · 전/후 · 개념 모음 · 퀴즈 |
| `q` | 오늘 복습 바로 시작 (보기 줄 끝에 `q: 복습 n개`가 보일 때) |
| `p` · `n` | 이전 · 다음 노트 (지난 세션 노트까지) |
| `t` · `e` · `r` · `i` | 노트 아래에서: 이 노트 퀴즈 · 더 쉽게 · 예시로 따라가기 · 질문하기 |
| `w` | 노트 쓰기 · 다시 쓰기 |
| `Esc` | 대화 입력칸으로 돌아가기 (패널은 그대로) |
| `ctrl+x tab` | 대화 입력칸에서 패널로 (패널 클릭도 됩니다) |

퀴즈 보기의 키는 [퀴즈 풀기](#퀴즈-풀기)에 있습니다. 버튼 앞에 키가 적혀 있고(`2: 전/후`), 마우스로 눌러도 됩니다.
숫자 키는 한/영 상관없이, 글자 키는 영문 상태에서 누릅니다. 패널이 키를 받고 있지 않으면 보기 줄 아래에 `ctrl+x tab: 패널 고르기 · 숫자 키는 한/영 상관없이, 글자 키는 영문 상태에서`가, 받고 있으면 `Esc: 대화로 돌아가기 · 글자 키는 영문 상태에서`가 보입니다.

### 보기 바꾸기

패널 위쪽 보기 줄은 늘 `1: 노트 · 2: 전/후 · 3: 개념 모음 · 4: 퀴즈`입니다. 지금 보는 보기는 굵게 밑줄이 쳐집니다. 보기 이름을 클릭해도 됩니다.
노트가 아직 없으면 `2: 전/후`만 빠지고 번호는 그대로입니다.

오늘 복습할 개념이 남아 있으면 보기 줄 끝에 노란 `●`와 `q: 복습 3개`가 붙습니다.
`q`를 누르면 퀴즈 보기로 가고, 풀던 문제가 없으면 `문제를 만드는 중입니다…`가 뜨면서 바로 새 문제를 받습니다. 풀던 문제가 있으면 그 문제의 답 칸으로 갑니다.
대화 입력칸에서 `/learn 복습`을 치면 패널을 열면서 이 `q`까지 한 번에 합니다.

노트 보기와 전/후 보기 맨 위에는 `노트 2/5 · 10:12 · 파일 2개 · +5 −1`처럼 지금 노트의 자리와 바뀐 양이 나옵니다.
노트에서 뺀 파일이나 가린 비밀값이 있으면 그 아래 줄에 `노트에서 뺀 파일 1개 · 비밀값 1곳 가림`이 흐리게 나옵니다(좁은 패널에서도 잘리지 않게 따로 한 줄입니다). 그 아래 `◀ 이전`(`p`) · `다음 ▶`(`n`)으로 노트를 오가고, `요청:` 줄에 그 턴의 요청이 보입니다.

### 전/후: 무엇이 달라졌는지 한눈에

노트의 **무엇이 바뀌었나**는 코드가 하던 일(`− 전`, 빨강)과 이제 하는 일(`+ 후`, 초록), 그 차이가 드러나는 예(`→ 예`)를 한 줄씩 보여 줍니다.

**전/후** 보기(`2`)는 맨 위에 그 세 줄을 다시 보여 주고, 바뀐 곳마다 원래 코드(전)와 바뀐 코드(후)를 파일의 줄 번호 그대로 놓습니다.

- 바뀌지 않은 줄은 흐리게, 바뀐 줄은 앞에 `−`(전) · `+`(후)를 붙입니다.
- 한 줄을 고친 것이면 **그 줄에서 바뀐 낱말만 굵은 색**으로 표시합니다. 예: `var n = 0` → `let n = 0`에서는 `var`와 `let`만.
- 거의 새로 쓴 줄은 줄 전체를 색으로, 새로 만든 파일은 코드 그대로 보여 줍니다.
- 맨 아래에는 노트에서 뺀 파일이 이름과 까닭으로 나옵니다. 예: `노트에서 뺀 파일: .env (비밀값이 들 수 있는 파일) · package-lock.json (잠금·생성 파일)`

맨 위 그림의 "전/후"가 이 보기입니다.

### 노트 아래에서 바로

노트 맨 아래 `이 노트로` 줄에서 이어 갑니다.

- `t` **이 노트 퀴즈**: 방금 읽은 노트의 개념으로, 그 노트의 코드에서 문제를 받습니다. 결과를 맞히는 문제(예측)와 코드를 바꿔 보는 문제(바꿔 보기)만 내고, 노트에 적힌 정의를 그대로 되묻지 않습니다. 퀴즈 제목도 `이 노트 퀴즈`로 보입니다.
- `e` **더 쉽게**: 원래 노트는 그대로 두고, 노트 아래에 `▶ 더 쉽게`로 쉬운 말과 일상의 비유를 넣은 설명을 덧붙입니다. 설정한 설명 수준과 상관없이 입문자 기준으로 씁니다. 원래 노트와 나란히 견주어 읽을 수 있습니다.
- `r` **예시로 따라가기**: 예시 입력 하나로 바뀐 코드를 한 단계씩 따라갑니다(`▶ 예시로 따라가기`). 단계마다 변수 값이 어떻게 바뀌는지, 바뀌기 전 코드였다면 어디서 결과가 갈리는지 짚어 줍니다.
- `i` **질문하기**: 노트 아래 질문칸에 궁금한 것을 적고 Enter. 그 노트와 코드를 근거로 짧게 답하고, 답은 노트 아래에 남습니다.
  이어서 물으면 앞의 질문과 답을 읽고 답합니다. 대화창의 Claude에게 묻는 것과 달리 코드를 고치지 않고, 저렴한 모델이 답합니다.
- `w` **다시 쓰기**: 줄 끝에 흐리게 있습니다. 노트를 처음부터 다시 씁니다. 다시 쓰다 실패하면 원래 노트는 그대로 둡니다.

`e`·`r`·질문은 할 때마다 모델 호출 한 번이고, 개념 수와 학습 기록은 바뀌지 않습니다. 노트 아래에는 최근 질문과 답 2개가 보이고(노트마다 3개까지 남음), 그보다 오래된 것은 일지에 있습니다.

### 퀴즈 풀기

`4`로 퀴즈 보기를 열고 `s`로 문제를 받습니다(최대 3문제, 모델 호출 한 번). 복습할 때가 된 개념부터, 그 개념을 배운 노트의 **내 코드**를 보여 주며 묻습니다.
세 문제는 되도록 서로 다른 노트에서 고릅니다. 다만 때가 된 개념이 먼저라, 때가 된 개념이 한 노트에만 있으면 그 노트 것만 나옵니다. 복습할 개념이 3개보다 적으면 곧 때가 될 개념으로 채웁니다.

문제 제목에 유형이 붙습니다(`문제 1/3 · 예측`).

- **예측**: 코드를 보여 주고 출력이나 값을 맞히게 합니다. 값이 같으면 설명이 없어도 맞힘입니다.
- **왜**: 어떤 줄을 빼거나 바꾸면 어떻게 되는지, 왜 그렇게 썼는지 묻습니다.
- **바꿔 보기**: 바라는 동작을 말하고 어느 줄을 어떻게 바꿀지 묻습니다. 바라는 대로 동작하면 정답과 다른 코드여도 맞힘입니다.

**답은 적고 Enter**: 문제가 나오면 커서가 `내 답` 칸에 있습니다. 패널로 키를 옮길 때(`ctrl+x tab`·클릭·`/learn 복습`)도 풀던 문제의 `내 답` 칸에서 시작합니다. 답을 적고 Enter를 누르면 `채점하는 중입니다…`가 뜨고, Claude가 정답과 비교해 **맞힘 · 거의 맞음 · 틀림**과 한두 문장 피드백을 줍니다.
채점이 끝나면 커서가 다음 문제의 `내 답` 칸으로, 마지막 문제 뒤에는 `s: 새 문제 받기`로 갑니다. 그래서 한/영을 바꾸지 않고 한글로 답을 적으며 이어 풀 수 있습니다.

| 키 | 하는 일 |
| --- | --- |
| Enter | `내 답` 칸에서 채점받기 |
| `h` | 힌트: 답을 말하지 않고 떠올릴 실마리만 보여 줍니다 |
| `a` | 정답만 보기. 그다음 `o`(맞혔어요) · `x`(틀렸어요)로 스스로 채점합니다 |
| `f` | 채점 바꾸기: Claude의 채점이 이상하면 맞힘 ↔ 틀림을 바꿉니다. 복습 단계도 처음부터 그렇게 채점한 것처럼 돌아갑니다 |
| `n` | 이 개념을 배운 노트로 가기: Claude가 틀림·거의로 채점한 문제 아래에 나옵니다. 그 노트에서 `r`로 코드를 따라가 보세요. 노트가 패널에 없으면 `/learn 찾기 개념 이름`을 안내합니다 |
| `s` | 새 문제 받기 (처음에는 `퀴즈 시작`). 풀던 문제가 남았으면 `풀던 문제 n개가 남았습니다 · s를 한 번 더 누르면 새 문제를 받습니다`가 뜨고, 바로 한 번 더 눌러야 새 문제를 받습니다(그사이 다른 키를 쓰면 처음부터) |
| `i` | `내 답` 칸으로 가기 |

`내 답` 칸에 커서가 있는 동안 글자 키와 숫자 키는 답으로 들어갑니다. 칸 아래에 흐리게 `답 칸에서 Enter: 채점 · Tab: 버튼으로 (h 힌트 · a 정답 · 1~4 보기)`가 보입니다. `Tab`으로 버튼에 간 뒤 `h`·`a`·`1`~`4`를 누르거나, 버튼을 마우스로 누르세요.
답 칸이 기다리는 동안 보기 줄 아래 안내도 바뀝니다. 키가 대화에 있으면 `ctrl+x tab: 답 칸으로 · 보기를 바꾸려면 그 뒤 Tab · 글자 키는 영문 상태에서`, 패널에 있으면 `Esc: 대화로 돌아가기 · 답은 한/영 상관없이, 버튼의 글자 키는 영문 상태에서`입니다.

채점한 문제는 위에 `✓ 맞힘` · `△ 거의 맞음` · `✗ 틀림` 한 줄로 남습니다. 힌트를 봤으면 `· 힌트 봄`, 정답을 보고 맞힘으로 채점했으면 `· 정답 봄`이 붙습니다. 방금 Claude가 채점한 문제는 다음 문제를 채점할 때까지 피드백·내 답·정답이 펼쳐져 있습니다.
퀴즈와 채점은 저장되므로 Claude Code를 다시 켜도 이어서 풉니다. 모바일 앱은 입력칸이 없어 `a`·`o`·`x`로 풀거나, 대화창에 `/learn 퀴즈 1 내 답`으로 답합니다.

### 간격 반복 복습

배운 개념은 **잊을 때쯤** 다시 나옵니다. 직접 떠올려 맞힐 때마다 간격이 늘어납니다.

| 단계 | 0 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- | --- |
| 다음 복습 | 1일 뒤 | 3일 뒤 | 7일 뒤 | 14일 뒤 | 30일 뒤 | 60일 뒤 |

- **퀴즈로 떠올린 것만 복습으로 칩니다.** 노트에서 다시 만난 개념(`다시 만난 개념 for...of 반복문 ×3`)은 복습 날짜를 바꾸지 않습니다.
- 퀴즈를 아직 안 본 개념은 처음 만난 날부터 1일 뒤(노트에서 다시 만났으면 3일 뒤)에 나옵니다.
- 때가 된 개념을 **답을 직접 적어 맞히면** 한 단계 오릅니다. 때가 되기 전에 맞힌 것이나 같은 날 다시 맞힌 것은 단계를 그대로 두고 그날부터 다시 셉니다.
- **힌트를 보거나 정답을 보고** 맞히면(`a` 뒤 `o`, `/learn 퀴즈 정답` 뒤 `맞음` 포함) 단계는 그대로이고 같은 간격 뒤에 다시 나옵니다. 간격을 늘리려면 먼저 떠올려 답을 적으세요.
- **거의 맞으면** 한 단계 내려갑니다(조금 더 빨리 다시 나옵니다).
- **틀리면** 0단계로 돌아가 바로 다음 퀴즈 맨 앞에 나옵니다.
- 복습 순서는 틀린 개념 → 퀴즈로 본 개념(오래 밀린 것부터) → 아직 퀴즈를 안 본 개념(최근 배운 것부터)입니다.

**오늘 복습은 하루 10문제까지**입니다. 복습할 개념이 있으면 프롬프트 아래 상태줄에 `학습 노트 · 오늘 복습 3개 · /learn 복습`이 뜹니다.
그날 채점한 문제만큼 줄고, 10문제를 채점하면 상태줄이 내려갑니다. 퀴즈 끝 줄에는 `오늘 복습을 마쳤습니다 · 남은 개념은 내일 나옵니다`가 나옵니다.
복습할 개념 전체 수는 개념 모음(`3`)과 `/learn 기록`에서 봅니다. 상태줄은 설정 `reviewReminder`로 끕니다.

**졸업**: 마지막 단계(60일)에서 때가 되어 또 답을 직접 적어 맞히면 아는 개념이 됩니다. 퀴즈 끝에 `졸업: 구조 분해 할당`이 나옵니다. 아는 개념은 아래 "아는 개념"처럼 다룹니다.

### 개념 모음과 학습 기록

- 노트의 "배울 개념"을 프로젝트를 넘어 모읍니다. 개념 모음(`3`) 맨 위에 `배운 개념 12개 · 최근 7일 새로 3 · 연속 3일째 · 퀴즈 4/6`이 한 줄로 나옵니다.
- 개념마다 만난 횟수, 최근에 만난 때, 마지막 퀴즈, 최근 설명, 그 개념이 나온 노트(누르면 그 노트로)가 있습니다. 복습 상태는 만난 횟수 바로 뒤에 붙습니다: `×2 · 다음 복습 3일 뒤 · 최근 10-08`(`퀴즈 틀림` · `아직 떠올려 본 적 없음`). 좁은 패널에서도 보이도록 날짜에는 시각을 붙이지 않습니다.
- 그 위의 `복습할 개념 n개`에 틀린 것부터 다섯 개가 보이고, 오늘 몫이 남았으면 `q로 복습`을 안내합니다.
- 노트 아래에는 그 노트에서 `새로 배운 개념`과 `다시 만난 개념 for...of 반복문 ×2`가 나뉘어 나옵니다.
- 이미 배운 개념 이름을 모델에 알려 주므로 같은 개념은 같은 이름으로 쌓입니다. "구조 분해 할당 (Destructuring)"과 "구조 분해 할당"처럼 표기만 다른 이름은 한 개념으로 셉니다. 그래도 갈라졌으면 `/learn 합치기 A = B`로 합칩니다.
- **아는 개념**: 이미 아는 개념은 `/learn 안다 const 선언, 화살표 함수`처럼 쉼표로 여럿 표시하고, `/learn 모른다 const 선언`으로 되돌립니다. 졸업한 개념도 아는 개념이 됩니다.
  아는 개념은 오늘 복습 수 · 퀴즈 · 개념 목록에서 빠지고, 개념 모음 맨 아래 `아는 개념 12개 · …` 한 줄로 접힙니다. 다음 노트부터는 그 개념을 배울 개념으로 다시 가르치지 않습니다.
  퀴즈로 3단계 이상 익힌 개념은 노트에서 `(복습)` 한 줄로만 짚고, 남는 자리를 새 개념에 줍니다.
- **연속 학습일**: 노트가 쓰였거나 퀴즈를 채점한 날을 셉니다. 날짜별 기록은 최근 120일을 모든 프로젝트 합산으로 남깁니다.
- **`/learn 기록`**: 연속 학습일, 최근 7일(노트 · 새 개념 · 다시 만난 개념 · 퀴즈), 최근 30일 정답률, 복습할 개념(`클로저 (퀴즈 틀림)`처럼)과 오늘 몫, `최근 7일 노트: 토 1 · 금 0 · …` 한 줄, 배운 개념 목록(많이 만난 순 20개), 아는 개념 한 줄, 학습 노트의 모델 호출 수를 한 번에 보여 줍니다.

## 대화로 묻기

대화창에 "지난주에 배운 거 정리해 줘", "복습할 개념 뭐야?", "const 노트 찾아 줘"처럼 그냥 물어도 됩니다.
Claude가 learn-notes의 **읽기 전용 학습 기록 도구**(`mcp__learn-notes__notes`)를 불러 내 노트와 개념 모음을 읽고 답합니다. 하위 명령을 외우지 않아도 됩니다.

- 도구가 주는 것: 찾기(이 프로젝트 노트와 모든 프로젝트의 맞는 개념) · 학습 기록(`/learn 기록`과 같되 개념 설명은 뺀 내용) · 지금 복습할 개념과 오늘 몫 · 한 기간(오늘 · 어제 · 이번주 · 최근 7일 · 날짜)에 이 프로젝트에서 쓴 노트와 그 개념 · 노트 하나의 전문과 그 아래 질문과 답.
- 노트 본문은 **지금 프로젝트의 것만** 줍니다. 개념은 프로젝트를 넘어 주지만 이름 · 만난 횟수 · 복습 상태만 주고 설명은 주지 않습니다. 한 번에 4,000자까지이고, 비밀값은 가린 뒤 줍니다.
- learn-notes 쪽 모델 호출은 없습니다. 도구의 답은 대화에 들어가 메인 Claude가 읽습니다.
- 읽기 전용이라 권한 창 없이 씁니다. 막고 싶으면 `permissions.deny`에 `mcp__learn-notes__notes`를 넣습니다. 설정 규칙이나 훅이 권한 창을 요구하면 그대로 따릅니다.
- Claude Code가 이 도구를 받아들였을 때만 동작합니다. 그때 `/learn 도움말` 맨 위에 `대화창에 그냥 물어봐도 됩니다: "오늘 배운 거 알려 줘"`가 나옵니다. 이 줄이 없으면 `/learn` 명령을 쓰세요.

### 팀 규칙 파일 `.claude/learn-notes.md`

프로젝트 폴더의 `.claude/learn-notes.md`에 팀 규칙과 용어를 적어 저장소에 커밋하면, 팀원 모두의 노트가 그것을 따릅니다. 새 명령은 없습니다.
파일은 Claude Code를 켠 폴더(`/cd`로 옮겼으면 옮긴 폴더) 아래에서 찾습니다. 저장소 맨 위에 두고, 팀원에게도 저장소 맨 위에서 Claude Code를 켜라고 알려 주세요.

```markdown
## 규칙
- API 호출은 src/lib/fetcher.ts의 fetcher로 감쌉니다
- 바뀌지 않는 값은 const로 선언합니다

## 용어
- **불변 바인딩**: const로 묶은 이름. 다시 대입할 수 없습니다
- **fetcher**: 우리 팀의 API 호출 함수

## 빼기
- legacy/**
- *.generated.ts
- `docs/old drafts/**` 공백이 든 경로는 백틱으로 감쌉니다
```

- **`## 규칙`**: 글머리표 한 줄이 규칙 하나입니다. 노트의 "왜 이렇게 바꿨을까"에 바뀐 코드와 직접 닿는 규칙이 있을 때만 `팀 규칙: …` 한 줄이 붙고, 규칙과 달라 보이면 `팀 규칙과 다를 수 있음: …`으로 단정하지 않고 적습니다. 노트 아래 질문(`i`, `/learn 질문`)도 규칙을 근거로 답합니다.
- **`## 용어`**: `- **이름**: 설명` 꼴로 씁니다. 배울 개념이 용어에 있으면 그 이름을 글자 그대로 써서, 팀원 모두의 개념 모음에 같은 이름으로 쌓입니다.
- **`## 빼기`**: 노트에 내용을 싣지 않을 경로 패턴입니다. 설정 `excludePaths`와 합쳐지고, 쓰는 법도 같습니다([설정](#설정) 참고). 한 줄에 하나 또는 쉼표로 나눠 쓰고, 패턴 뒤의 낱말은 설명으로 보고 건너뜁니다. 공백이 든 경로는 백틱으로 감쌉니다. `!`로 다시 넣는 패턴은 지원하지 않습니다.
- 영어 제목(`## Rules` · `## Terms`(`Glossary`) · `## Exclude`)도 됩니다. 이 세 제목 밖의 줄과 `<!-- 주석 -->`은 읽지 않습니다.
- 규칙과 용어는 합쳐 앞 3,000자만 모델에 보냅니다(저장소 내용이 프롬프트에 들어가기 때문입니다). 파일을 고치면 다음 턴부터 다시 읽습니다. 200KB를 넘거나 `permissions.deny`의 읽기 금지 규칙에 걸린 파일은 읽지 않습니다.
- 노트가 아직 없는 패널에 `이 저장소의 팀 규칙 파일을 읽었습니다 (규칙 2 · 용어 2 · 빼기 3)`가 흐리게 나옵니다. 제목을 못 찾으면 `… 읽은 것이 없습니다 · 제목을 ## 규칙 · ## 용어 · ## 빼기로 씁니다`가 나옵니다.
- 규칙 판정은 모델의 참고 의견입니다. 코드 리뷰를 대신하지 않습니다.

### 저장소에서 팀원에게 자동으로 켜기

저장소의 `.claude/settings.json`에 아래 두 키를 넣어 커밋하면, 그 저장소를 연 팀원에게 learn-notes가 따로 설치하지 않아도 켜집니다.
팀원이 그 폴더를 처음 열 때 나오는 **폴더 신뢰 창을 받아들인 뒤**부터 적용됩니다. learn-notes는 마켓플레이스 안의 경로로 실려 있어서, 마켓플레이스가 등록되면 그대로 불러옵니다.

```json
{
  "extraKnownMarketplaces": {
    "learn-notes": {
      "source": { "source": "github", "repo": "Owen-YC/learn-notes" }
    }
  },
  "enabledPlugins": {
    "learn-notes@learn-notes": true
  }
}
```

- 끄고 싶은 팀원은 자기 `.claude/settings.local.json`에 `"enabledPlugins": { "learn-notes@learn-notes": false }`를 둡니다.
- 설정값(`level`·`model`·`excludePaths`·`dailyAutoNotes`)은 저장소 설정으로 정할 수 없습니다. Claude Code는 플러그인 설정(`pluginConfigs`)을 사용자 설정과 관리 설정에서만 읽습니다. 팀 규칙·용어·뺄 경로는 위의 팀 규칙 파일로 정하세요.

### 관리자: 조직 전체에 설치하고 기본값 잠그기

조직의 **관리 설정**(managed settings)에 같은 두 키를 넣으면 모든 사람에게 설치되고 켜집니다(개인이 끌 수 없음). 여기에 `pluginConfigs`를 더하면 설정값이 **잠깁니다**. 팀원의 `/config`에는 learn-notes 항목에 그 값이 보이지만 바꿀 수 없습니다. 관리 설정에 넣지 않은 항목은 각자 `/config`에서 고릅니다.

```json
{
  "extraKnownMarketplaces": {
    "learn-notes": {
      "source": { "source": "github", "repo": "Owen-YC/learn-notes" },
      "autoUpdate": true
    }
  },
  "enabledPlugins": {
    "learn-notes@learn-notes": true
  },
  "pluginConfigs": {
    "learn-notes@learn-notes": {
      "options": {
        "level": "beginner",
        "model": "haiku",
        "excludePaths": "legacy/**, *.generated.ts, fixtures/",
        "dailyAutoNotes": 40
      }
    }
  }
}
```

- 관리 설정을 나눠 주는 길은 셋입니다: claude.ai의 **조직 설정 > Claude Code > Managed settings**(Teams·Enterprise), MDM, 또는 시스템 폴더의 `managed-settings.json`(macOS `/Library/Application Support/ClaudeCode/`, Linux·WSL `/etc/claude-code/`, Windows `C:\Program Files\ClaudeCode\`). 이미 쓰는 관리 설정이 있으면 그 JSON에 위 키만 더합니다.
- `autoUpdate: true`를 두면 learn-notes 새 판이 나왔을 때 각자 업데이트하지 않아도 백그라운드에서 따라옵니다.
- `excludePaths`는 쉼표로 구분한 한 줄 문자열로, `dailyAutoNotes`는 숫자로 씁니다. `model`은 `haiku`나 `sonnet`만 받습니다.
- 클라우드 세션(claude.ai 웹·앱의 Claude Code)에는 claude.ai 콘솔의 관리 설정만 닿습니다. 자세한 규칙은 공식 문서 [조직의 플러그인](https://code.claude.com/docs/en/plugins/org)과 [관리 설정](https://code.claude.com/docs/en/managed-settings)에 있습니다.

### 권하는 도입 순서

1. 관리자 한 사람이 먼저 설치해 하루이틀 써 봅니다. `/learn 기록` 맨 아래의 모델 호출 수로 하루 사용량을 가늠합니다.
2. 저장소에 `.claude/learn-notes.md`(팀 규칙·용어·뺄 경로)와 `.claude/settings.json`(마켓플레이스와 `enabledPlugins`)을 커밋합니다. 규칙은 몇 줄로 시작합니다.
3. 조직 전체에 쓰거나 값을 잠가야 하면 관리 설정으로 `model`(haiku), `excludePaths`, `dailyAutoNotes`를 정합니다.
4. 팀에 [소개 글](#팀에-공유하기)과 안내서 PDF를 보냅니다. 입문자에게는 "숫자 키는 한/영 상관없이, 글자 키는 영문 상태에서"를 꼭 알려 주세요.
5. 1~2주 뒤 회고나 1:1에서 각자 `/learn 보고서`를 붙여 이야기 거리로 씁니다. 줄 세우기나 평가에는 쓰지 않습니다. 사용량을 보고 `dailyAutoNotes`를 조정합니다.

## /learn 명령

한글 명령이 기본이고, 괄호 안의 영어 이름도 됩니다.

| 명령 | 하는 일 |
| --- | --- |
| `/learn` | 학습 노트 패널 열기. 키는 대화 입력칸에 둡니다(패널로는 `ctrl+x tab`·클릭). 패널을 띄울 수 없는 화면이면 마지막 노트를 대화창에 적습니다 |
| `/learn 복습` (`review`) | 오늘 복습을 바로 시작: 패널을 퀴즈로 열고 커서를 `내 답` 칸에 둡니다. 풀던 퀴즈가 있으면 그 문제, 없으면 새 퀴즈. 오늘 복습할 개념이 없거나 오늘 몫을 마쳤으면 새 퀴즈를 만들지 않고 그렇다고 알려 줍니다. 패널을 띄울 수 없는 화면이나 클라우드 세션, 원격 제어·채팅 채널에서 보냈으면 문제를 대화창에 냅니다 |
| `/learn 퀴즈` (`quiz` · `문제`) | 대화창에서 풀기. 풀던 퀴즈가 있으면 다시 보여 줍니다(모델 호출 없음). 없으면 복습할 개념으로 새 퀴즈 (내 코드로 묻습니다). `시작` · `보기` · `계속` · `풀기`를 붙여도 같습니다 |
| `/learn 퀴즈 1 내 답` | 1번 답을 Claude에게 채점받기. 번호 없이 답만 적으면(`/learn 퀴즈 const는 다시 못 바꿔요`) 아직 안 푼 첫 문제로 채점하고 `1번 답으로 채점했습니다`를 붙입니다. 답이 `정답`·`힌트`·`맞`·`틀`·`채점` 같은 명령 낱말로 시작하거나 한 글자면 채점하지 않고 쓰는 법을 알려 줍니다 |
| `/learn 퀴즈 새로` (`새` · `new`) | 풀던 문제가 있어도 새 퀴즈 받기 |
| `/learn 퀴즈 힌트` | 지금 풀 문제 하나의 힌트 (`힌트 2`·`2 힌트`면 2번). 그 문제만 `힌트 봄`으로 적습니다 |
| `/learn 퀴즈 정답` | 지금 풀던 문제 하나의 정답 (`정답 3`이면 3번). 남은 문제는 계속 답을 적어 채점받습니다 |
| `/learn 퀴즈 맞음 2` · `틀림 2` | 정답을 본 뒤 스스로 채점. 이미 채점한 문제의 채점도 바꿉니다(복습 단계도 함께) |
| `/learn 정리` (`recap` · `요약`) | 오늘 배운 것 정리(한 일 · 핵심 개념 · 헷갈리기 쉬운 것 · 다음에 해 볼 것). `어제` · `이번주` · `최근 7일` · `2026-10-03`도 됩니다. 헷갈리기 쉬운 것은 그 기간에 퀴즈에서 틀린 개념부터 씁니다. 정리는 일지에 남습니다 |
| `/learn 질문 …` (`ask` · `묻기`) | 패널에서 고른 노트(없으면 마지막 노트)에 대해 묻기. 답은 패널의 노트 아래와 일지에도 남습니다 |
| `/learn 기록` (`stats` · `concepts` · `개념` · `통계`) | 연속 학습일 · 최근 7일 · 정답률 · 복습할 개념 · 배운 개념 · 모델 호출 수 |
| `/learn 보고서` (`report` · `보고`) | 코드 없는 학습 보고서를 클립보드와 파일로 (기본 최근 7일) |
| `/learn 찾기 말` (`find` · `검색`) | 모든 프로젝트의 노트에서 요청·내용·파일 이름·개념으로 찾기 |
| `/learn 일지` (`day`) | 이 프로젝트의 오늘 노트 목차. `어제` · `10-03` · `2026-10-03`도 되고, `/learn 일지 목록`은 일지가 있는 날짜. 목차 끝에 `다른 날: 10-02 · 09-30 · /learn 일지 10-02`가 붙습니다 |
| `/learn 마지막` (`last`) | 마지막 노트를 대화창에 |
| `/learn 합치기 A = B` (`merge`) | 이름만 다른 같은 개념 합치기(A를 B로). 거꾸로(`B = A`) 하면 되돌립니다 |
| `/learn 안다 이름` (`know`) · `/learn 모른다 이름` (`unknow`) | 아는 개념으로 표시해 복습·퀴즈에서 빼기 · 되돌리기. 쉼표로 여럿 |
| `/learn 안키` (`anki`) | 퀴즈 문제와 개념을 Anki 카드 파일로 |
| `/learn 비우기` (`clear`) | 이 프로젝트의 노트를 패널에서 비우기. 먼저 노트 수를 알려 주고, `/learn 비우기 확인`이어야 비웁니다(일지 파일과 개념 모음은 그대로) |
| `/learn 도움말` (`help` · `도움`) | 명령 목록 |

1.5까지 쓰던 `/learn days`(`날짜`)는 `/learn 일지 목록`과 같은 답을 냅니다. `/learn save`(`저장`)는 이제 할 일이 없어 안내만 합니다. 노트는 저절로 저장되고, 파일에 쓰지 못한 노트는 다음 노트를 저장할 때 함께 저장됩니다.

## 설정

`/config`의 learn-notes 항목에서 바꿉니다. 바꾸면 모드가 다시 불려 바로 적용됩니다. 터미널에서는 `claude plugin configure learn-notes@learn-notes`.
조직 관리자가 잠근 항목은 `/config`에 보이지만 바꿀 수 없습니다([관리자: 조직 전체에 설치하고 기본값 잠그기](#관리자-조직-전체에-설치하고-기본값-잠그기) 참고).

| 항목 | 기본값 | 설명 |
| --- | --- | --- |
| `autoNote` | 켜짐 | 끄면 바뀐 코드만 모으고 노트는 패널에서 `w`로만 씁니다 (그만큼 모델 비용이 들지 않습니다) |
| `model` | `haiku` | `haiku` · `sonnet`. 노트·퀴즈·채점·질문·정리에 씁니다. haiku가 가장 싸고 빠릅니다 |
| `level` | `beginner` | `beginner`(용어를 쉬운 말로) · `intermediate`(개념 위주) · `advanced`(설계·트레이드오프) |
| `autoOpen` | 켜짐 | 첫 노트가 생기면 대화 오른쪽에 패널을 엽니다. 터미널이 좁으면 대신 알림만 띄웁니다(칸 수는 아래 "자세히") |
| `autoSave` | 켜짐 | 날짜별 마크다운 일지에 노트를 씁니다. 끄면 파일을 쓰지 않습니다(패널과 지난 노트에는 남습니다). 일지·`concepts.md`·정리·질문·보고서 파일을 모두 쓰지 않습니다 |
| `reviewReminder` | 켜짐 | 복습할 개념이 생기면 프롬프트 아래에 오늘 복습할 개수를 띄웁니다 (하루 10개까지) |
| `saveDir` | (비움) | 비우면 `~/.claude/learning-notes`. `~`로 시작하면 홈 폴더 기준 |
| `excludePaths` | (비움) | 노트에서 뺄 파일. 쉼표로 구분한 경로 패턴입니다. 예: `legacy/**, *.generated.ts`. 맞는 파일은 `(설정으로 뺀 파일)`로 이름만 남습니다 |
| `dailyAutoNotes` | `0` | 하루 자동 노트 최대 개수. 0이면 제한이 없습니다. 한도에 닿으면 그날은 턴이 끝나도 노트를 쓰지 않고, 패널에서 `w`를 누를 때만 씁니다 |

`excludePaths`(와 팀 규칙 파일의 `## 빼기`) 패턴은 `.gitignore`처럼 읽습니다.

- `/`가 없는 패턴은 아무 깊이의 파일이나 폴더 이름과 맞습니다. `*.generated.ts`, `fixtures`(그 폴더 아래 전부).
- `/`가 있는 패턴은 프로젝트 맨 위부터 그 경로와 그 아래 전부입니다. `legacy/**`, `src/gen`.
- 끝의 `/`는 폴더만(`fixtures/`), 앞의 `/`는 프로젝트 맨 위만(`/scripts`) 뜻합니다.
- `**`는 아무 경로, `*`는 이름 한 칸 안, `?`는 한 글자입니다. 대소문자는 가리지 않습니다.

1.5.x에서 `model`을 `opus`로 골랐다면, 이제 선택지에 없어 기본값 `haiku`로 돌아갑니다.

## 노트가 안 생겨요

하나씩 확인해 보세요.

1. **그 턴에 파일이 바뀌었나요?** 질문에 답만 한 턴은 노트가 없습니다. Claude가 파일을 만들거나 고친 턴에만 생깁니다.
2. **패널이 열려 있나요?** `/learn`으로 엽니다. 대화 오른쪽에 붙으려면 `/tui fullscreen`(전체 화면)이어야 하고, 아니면 프롬프트 위에 열립니다.
   패널을 띄울 수 없는 화면(전체 화면이 아니고 패널이 열려 있지 않을 때, 클라우드 세션)에서는 노트가 준비되면 대화창에 흐린 줄 `학습 노트 · 한 줄 요약 · /learn으로 보기`가 남습니다. 이 줄은 Claude에게 보내지 않습니다.
   패널을 닫았거나 다른 패널 뒤에 있으면 토스트로 알립니다.
3. **단축키가 안 먹나요?** `/learn`은 패널만 열고 키는 대화 입력칸에 둡니다. 패널을 클릭하거나 `ctrl+x tab`을 누르면 키가 패널로 갑니다. 오늘 복습은 `/learn 복습`이 키까지 한 번에 옮깁니다.
   숫자 키(`1`~`4`)는 한/영 상관없이 눌립니다. `ㅂ`·`ㅅ` 같은 글자가 대화 입력칸에 찍힌다면 한/영이 한글 상태입니다. 한글 상태에서는 `q`가 `ㅂ`, `t`가 `ㅅ`으로 들어가 글자 단축키가 먹지 않습니다. 한/영 키로 영문 상태로 바꾸세요.
4. **설치한 폴더가 다른가요?** 다른 폴더에서 설치했다면 `/plugin`의 Installed 탭에 learn-notes가 있는지 보고, 없으면 빠른 시작의 두 줄을 다시 입력합니다.
5. **노트 칸이 빨간 글씨인가요?** 이유가 적혀 있습니다. `서버가 붐빕니다` · `요청 한도에 걸렸습니다`는 잠시 뒤 `w`로 다시 쓰고, `모델을 부를 수 없습니다`는 `/config`에서 다른 모델을 고르세요. `로그인이 필요합니다`는 `/login`.
6. **임시 폴더의 파일만 바뀌었나요?** 프로젝트 밖 임시 폴더의 파일은 Claude의 작업 파일로 보고 빼놓습니다(아래 "자세히").
7. **노트에서 빼는 파일만 바뀌었나요?** `.env` 같은 비밀 파일, `package-lock.json` 같은 잠금·생성 파일, `excludePaths`나 팀 규칙 파일의 `## 빼기`에 맞는 파일, 읽기 금지 규칙에 걸린 파일만 바뀐 턴은 노트도 모델 호출도 없습니다([비용과 개인정보](#비용과-개인정보) 참고).
8. **띄어쓰기·줄바꿈만 바뀌었나요?** JS·TS·CSS·SCSS·JSON·HTML·Vue·Svelte 파일에서 띄어쓰기와 줄바꿈만 바뀐 턴은 노트 칸에 `띄어쓰기·줄바꿈만 바뀌어 노트를 쓰지 않았습니다 · w로 쓰기`가 남습니다. 쓰고 싶으면 `w`를 누릅니다. Python·YAML은 들여쓰기가 뜻을 바꾸므로 늘 노트를 씁니다.
9. **하루 한도에 닿았나요?** `dailyAutoNotes`를 정했으면(관리자가 잠갔을 수도 있습니다) 한도를 넘은 턴에는 노란 글씨로 `오늘 자동 노트 한도(40개)에 닿았습니다 · w를 누르면 씁니다`가 남고, 그날 처음 한 번 토스트가 뜹니다. `w`로 쓰는 노트와 퀴즈·질문은 막지 않습니다.
10. **자동 노트가 꺼져 있나요?** `자동 노트가 꺼져 있습니다. w로 노트를 쓰거나 2로 전/후 코드를 보세요.`가 보이면 `/config`의 `autoNote`가 꺼진 것입니다.

## 비용과 개인정보

### 모델 호출

- 파일을 바꾼 턴마다 자동 노트로 모델 호출이 **한 번** 일어납니다(기본 haiku, 노트 하나에 바뀐 코드 최대 약 14,000자).
- 직접 하는 것은 할 때마다 한 번씩입니다: 퀴즈 받기 · 답 채점 · 질문 · 예시로 따라가기 · 더 쉽게 · 다시 쓰기 · 정리.
- 모델을 부르지 않는 것: `/learn 기록` · `보고서` · `찾기` · `일지` · `마지막` · `안키`, 풀던 퀴즈 다시 보기, 힌트, 정답 보기, 대화로 묻기의 학습 기록 도구.
- 모델을 부르지 않고 넘어가는 턴: 뺀 파일만 바뀐 턴, 띄어쓰기·줄바꿈만 바뀐 턴, 하루 한도(`dailyAutoNotes`)를 넘은 턴.
- 호출은 지금 쓰는 Claude Code 계정으로 나갑니다. 메인 세션과 같은 계정의 요청 한도를 나눠 씁니다.
- `/learn 기록` 맨 아래에 사용량이 나옵니다: `학습 노트의 모델 호출: 오늘 12번 (자동 노트 9) · 최근 7일 61번 · 입력 약 18만 · 출력 약 3만 토큰`.
  입력에는 캐시로 읽고 쓴 토큰도 들어 있고, 응답이 온 호출은 오류여도 셉니다. 금액은 계정마다 달라 적지 않습니다.

### 노트에 싣지 않는 파일

아래 파일은 바뀌어도 **내용을 모으지 않습니다.** 모델 호출 · 일지 · 플러그인 저장소 어디에도 내용이 가지 않고, 이름과 까닭만 남습니다(노트 머리줄 아래 줄의 `노트에서 뺀 파일 n개`, 전/후 보기 맨 아래, 일지의 `**뺀 파일**`, 노트마다 12개까지). 노트를 쓰는 모델에게는 그 파일의 값을 짐작하지 말고 이름으로만 말하라고 알립니다.

| 까닭 | 파일 |
| --- | --- |
| 비밀값이 들 수 있는 파일 | `.env`, `.env.local`처럼 `.env`로 시작하는 파일(`.env.example` · `.sample` · `.template` · `.dist`는 보통 코드로 다룸), `*.pem` · `*.key` · `*.p12` · `*.pfx`, `*.tfvars` · `*.tfvars.json` · `*.tfstate`, `id_rsa*` · `id_ed25519*` · `id_ecdsa*` · `id_dsa*`, `.npmrc` · `.pypirc` · `.netrc` · `.git-credentials`, 이름에 `credentials`가 든 `.json`, `service…account….json`, `secrets.*`, `~/.aws/credentials`, `.envrc` · `app.env` · `.env-prod`, `.pgpass`, `key.properties`, `*.jks` · `*.keystore` |
| 잠금·생성 파일 | `package-lock.json` · `npm-shrinkwrap.json` · `yarn.lock` · `pnpm-lock.yaml` · `bun.lock(b)` · `Cargo.lock` · `poetry.lock` · `Pipfile.lock` · `composer.lock` · `Gemfile.lock` · `go.sum`, `*.min.js` · `*.min.css` · `*.map`, 아무 깊이의 `node_modules/` · `__snapshots__/`, 프로젝트 맨 위의 `dist/` · `build/` · `out/` · `.next/` · `coverage/` · `.turbo/` · `.vercel/` |
| 설정으로 뺀 파일 | `excludePaths`와 팀 규칙 파일의 `## 빼기`에 맞는 파일 |
| 조직 설정으로 읽기가 막힌 파일 | 관리 설정이나 내 설정의 `permissions.deny`에 `Read(./config/prod.yml)`처럼 읽기가 막힌 파일 |

비밀 파일은 값이 그대로 들어 있을 수 있어서, 잠금·생성 파일은 사람이 쓴 코드가 아니라 배울 것이 없고 길어서 비용만 들기 때문에 뺍니다. 이런 파일만 바뀐 턴은 노트도 모델 호출도 없습니다.

### «가림»으로 가리는 것

다른 파일의 바뀐 코드, 내 요청, Claude의 마지막 설명, 노트에 적은 질문 속 흔한 키 형식은 `«가림»`으로 바꿉니다. 변수 이름은 남기고 값만 바꿉니다.
모든 모델 호출 직전에 한 번 더 가리고(1.6.0 전에 저장된 노트·일지, 퀴즈에 적은 답도), `/learn` 명령의 답, 학습 기록 도구가 대화로 주는 답, `/learn 안키` 파일과 `concepts.md`도 가립니다.
1.6.0 전에 저장된 노트에 비밀·잠금·생성 파일이나 뺄 경로의 파일이 들어 있으면, 그 노트가 모델 호출·일지·명령 답으로 나갈 때 그 파일의 내용을 빼고 이름만 남깁니다.
노트 머리줄 아래 줄의 `비밀값 n곳 가림`은 바뀐 코드에서 가린 곳만 셉니다. 요청·설명·질문에서 가린 곳은 `«가림»`으로 보이지만 숫자에는 들지 않습니다.

| 가리는 것 | 예 |
| --- | --- |
| Anthropic · OpenAI 키 | `sk-ant-…`, `sk-proj-…`, `sk-…` (숫자가 든 것) |
| AWS 액세스 키 ID | `AKIA…`, `ASIA…` |
| GitHub 토큰 | `ghp_…`, `gho_…`, `ghu_…`, `ghs_…`, `ghr_…`, `github_pat_…` |
| Slack · Google · Stripe · GitLab | `xoxb-…` 등, `AIza…`, `sk_live_…` · `sk_test_…` · `rk_live_…`, `glpat-…` |
| npm · Hugging Face · Supabase | `npm_…`, `hf_…`, `sb_secret_…` |
| 봇 토큰 · 웹훅 주소 | Telegram · Discord 봇 토큰, Slack · Discord 웹훅 주소의 비밀 부분 (`hooks.slack.com/services/«가림»`) |
| JWT, Bearer 토큰 | `eyJ….….…`, `Bearer …` |
| 개인 키 | `-----BEGIN … PRIVATE KEY-----`와 END 사이 본문 (BEGIN·END 줄은 남김), 잘려 나온 60자 이상의 base64 줄 |
| 접속 문자열의 비밀번호 | `postgres://user:«가림»@host`, `redis://:«가림»@host` (mysql · mongodb+srv 등 다른 scheme도) |
| 비밀을 뜻하는 이름에 준 따옴표 값 | `password: "«가림»"`, `api_key = '«가림»'`, `clientSecret: "«가림»"` (이름에 password · secret · token · api_key · access_key · private_key가 든 것) |
| 이름이 KEY로 끝나는 따옴표 값 | `WEATHER_KEY = "«가림»"`, `serviceKey: "«가림»"`, `RIOT_KEY = "«가림»"` (값이 키 모양일 때만: 숫자와 글자가 섞인 16자 이상의 값, UUID 꼴. `storageKey = "theme"`은 그대로) |
| 이름이 PASS · PWD로 끝나는 따옴표 값 | `DB_PASS = "«가림»"`, `pass: "«가림»"` (글자만 있어도 가림. `renderPass: 'shadow'`처럼 낱말 이름은 그대로) |
| 대문자 dotenv 값 | `OPENAI_API_KEY=«가림»`, `DB_PASSWORD=«가림»`, `DB_PASS=«가림»`, `export AUTH_TOKEN=«가림»` |
| 설정 파일의 따옴표 없는 값 | `.properties` · `.ini` · `.cfg` · `.conf` · `.toml` · YAML에서 `password: «가림»`, `spring.datasource.password=«가림»`, `aws_secret_access_key = «가림»`, `apiKey: «가림»`, `mail.pass=«가림»` (`access_token: 3600` 같은 숫자, `password: Password` 같은 번역 라벨, `true` · 버전은 그대로) |

**못 가리는 것**도 있습니다. 흔한 형식만 잡기 때문입니다.

- 공백이 든 따옴표 값(`password: "correct horse battery"`), `config["password"] = "…"`처럼 이름이 따옴표 안에 든 것
- 코드 파일(`.js` · `.py` 등) 안의 따옴표 없는 값(설정 파일에서만 가립니다)
- 도구마다 다른 설정 형식: `.kube/config`의 `client-key-data`, `.docker/config.json`의 `auth`, Maven `settings.xml`의 `<password>` (이런 파일은 `excludePaths`에 넣으세요)
- 사내에서만 쓰는 토큰 형식, 이름으로 비밀임이 드러나지 않는 값
- 일부러 두는 것: `${DB_PASS}` · `$TOKEN` · `<your-key>` 같은 자리표시, `process.env.API_KEY`처럼 값이 아닌 것, `passwordLabel` · `tokenUrl`처럼 비밀에 "대한" 이름, `=====` 구분선, `package.json`의 의존성 버전(`"jsonwebtoken": "^9.0.2"`), `show ? "password" : "text"` 같은 삼항식, 한글 값(`"password": "비밀번호"`), 설정 파일의 `true` · 버전 · 문장

가림은 늘 켜져 있고 끄는 설정은 없습니다. 사내 비밀 파일이 따로 있다면 `excludePaths`나 팀 규칙 파일의 `## 빼기`에 넣으세요.

### 알아 둘 것

- **메인 Claude 세션은 이미 그 내용을 봤습니다.** Claude가 그 파일을 읽고 고쳤기 때문입니다. 이 모드가 막는 것은 **노트를 쓰려고 한 번 더 나가는 모델 호출**과 **일지·플러그인 저장소에 남는 사본**입니다. 대화에 비밀값을 붙여 넣지 않는 습관이 먼저입니다.
- 1.6.0 전에 쓴 일지 파일과 저장된 노트 자체는 고치지 않습니다(그 파일을 소급해 가리지 않음, 나갈 때만 가림). 옛 일지가 걱정되면 일지 폴더(`~/.claude/learning-notes/`)의 파일을 직접 확인하세요.
- 노트·일지·개념 모음·학습 기록·퀴즈·보고서 파일은 모두 내 컴퓨터에만 저장됩니다. 다만 `/learn` 명령의 답(기록·마지막 노트·대화창에 적은 보고서 등)과 학습 기록 도구의 답은 대화창에 들어가 메인 Claude도 읽습니다.

  같은 프로젝트에서 세션 둘을 동시에 써도 서로의 노트를 지우지 않고, 같은 노트는 더 나중에 고친 쪽이 남습니다. `/cd`로 프로젝트를 옮기면 패널도 그 프로젝트의 노트로 바뀝니다.
- **개념 모음**: 최근에 만난 400개. 일지 폴더의 `concepts.md`에 표로도 남습니다.
- **학습 기록과 모델 호출 기록**: 날짜별로 최근 120일. 모든 프로젝트 합산입니다.
- **퀴즈 문제**: 최근 300개(`/learn 안키`용).
- **보고서**: 일지 폴더의 `report-<첫날>_<끝날>.md`.
- **팀 규칙 파일**: 저장소의 것을 읽기만 하고 따로 저장하지 않습니다.
- 파일에 쓰지 못한 노트(폴더 권한 등)는 다음 노트를 저장할 때 함께 저장됩니다. 그 전에는 `학습 노트를 파일에 쓰지 못했습니다 · /config의 saveDir를 확인하면 다음 노트 때 함께 저장됩니다` 토스트가 한 번 뜹니다.
- `claude -p`(한 번 실행하고 끝나는 방식)에서는 노트를 다 쓰고 나서 끝납니다. 그만큼(보통 10초 안팎) 실행이 길어집니다.

</details>

<details>
<summary>패널이 저절로 열리는 때 (autoOpen)</summary>

- 첫 노트가 생기면 세션마다 한 번, 전체 화면 터미널에서 대화 오른쪽에 패널을 엽니다. 이때는 키를 가져가지 않으므로 작업 중인 입력이 끊기지 않습니다.
- 터미널이 144칸 이상일 때 열리고, 패널을 `/learn`으로 연 적이 있으면 110칸부터 열립니다(이전 세션 포함). 패널을 손으로 닫으면(`ctrl+x x`) 다시 144칸부터입니다. 그보다 좁으면 열지 않고 알림만 띄웁니다.
- `Esc`는 패널을 닫지 않고 키만 대화로 돌려줍니다.

</details>

<details>
<summary>보안 검토용</summary>

- 모드가 직접 여는 네트워크 연결이나 외부 프로그램 실행은 없습니다. 모델 호출은 Claude Code를 거쳐 지금 계정으로 나갑니다.
- 읽는 환경 변수: `CLAUDE_CODE_REMOTE` · `HOME` · `TEMP` · `TMP` · `TMPDIR` · `USERPROFILE`.
- 쓰는 곳: 일지 폴더(`saveDir`, 기본 `~/.claude/learning-notes`)의 일지 · `concepts.md` · `report-*.md` · `learn-notes-anki.txt`, 그리고 Claude Code의 플러그인 저장소.
- 셸 명령의 diff를 직접 만들 때는 명령에 이름이 나온 파일(300KB 이하)을 명령 전후로 읽습니다. 뺄 파일이면 비교만 하고 저장하거나 보내지 않습니다.
- 읽기 금지 규칙: `permissions.deny`의 `Read` 규칙(관리 설정 포함)을 Claude Code에 물어 따릅니다. PreToolUse 훅이나 자동 분류기로 막는 규칙은 반영하지 않습니다. 판정을 받지 못하면 허용으로 봅니다.
- 학습 기록 도구(`mcp__learn-notes__notes`)는 읽기 전용이고, 개념은 이름 · 만난 횟수 · 복습 상태만 줍니다(설명은 주지 않음). 권한 창 없이 허용하지만, deny 규칙과 설정 규칙·훅이 요구한 권한 창은 그대로 따릅니다.
- 팀 규칙 파일은 저장소 내용이므로 규칙과 용어를 3,000자로 잘라 프롬프트에 넣습니다. 링크로 커밋된 팀 파일은 링크가 가리키는 파일도 읽기 금지 규칙에 걸리지 않을 때만 읽습니다.

</details>

## 팀에 공유하기

팀 메신저에 그대로 붙여 넣을 수 있는 소개 글입니다.

```text
안녕하세요! 바이브코딩하면서 공부도 같이 되도록 Claude Code 모드를 하나 만들었어요. 이름은 learn-notes예요 📒

🤔 모드(MOD)가 뭐예요?
Claude Code에 기능을 덧붙이는 확장 프로그램이에요. 크롬 확장 프로그램처럼 한 번 설치하면 Claude Code 안에 새 명령과 패널이 생겨요.

✨ learn-notes가 해 주는 것
• Claude가 코드를 고치면, 턴이 끝날 때 "무엇이 왜 바뀌었고 무엇을 배울 수 있는지"를 학습 노트로 정리해 오른쪽 패널에 보여 줘요
• 코드가 전에 하던 일과 이제 하는 일을 한 줄씩, 차이가 드러나는 예시와 함께 보여 줘요
• 바뀌기 전/후 코드를 나란히 놓고, 바뀐 줄과 바뀐 낱말까지 색으로 표시해 줘요
• 노트 아래에서 바로 물어보고, 예시 하나로 코드를 따라가 보고, 더 쉬운 말로 다시 설명받을 수 있어요
• 배운 개념은 프로젝트가 달라도 계속 쌓이고, 잊을 때쯤 "내가 만든 코드"로 복습 퀴즈를 내요 (결과 맞히기 · 왜 · 바꿔 보기). 답을 적고 Enter를 누르면 Claude가 채점해 줘요
• .env 같은 비밀 파일은 노트에 싣지 않고, 코드 속 흔한 키 형식은 «가림»으로 가려요
• /learn 보고서 로 코드 없는 학습 기록을 만들어 1:1이나 회고에 붙일 수 있어요

🛠 설치 (2분)
Claude Code v2.1.289 이상이 필요해요 (claude --version 으로 확인)
1) Claude Code 안에서 아래 두 줄 입력
   /plugin marketplace add Owen-YC/learn-notes
   /plugin install learn-notes@learn-notes
2) Claude Code를 다시 켜고 /tui fullscreen (전체 화면이어야 패널이 오른쪽에 붙어요)
3) /learn 으로 패널 열기 → 평소처럼 코딩을 요청하면 몇 초 뒤 노트가 떠요
4) /learn 도움말 에 명령 목록이 나오면 성공!

💡 알아 두면 좋은 것
• 오늘 복습은 /learn 복습 한 번이면 돼요. 패널이 퀴즈로 열리고 바로 답을 적어 Enter
• 패널의 키를 쓰려면 ctrl+x tab (또는 패널 클릭), Esc 를 누르면 대화로 돌아가요
  1 노트 · 2 전/후 · 3 개념 모음 · 4 퀴즈 · q 오늘 복습
  노트 아래: t 이 노트 퀴즈 · e 더 쉽게 · r 예시로 따라가기 · i 질문하기
• 숫자 키는 한/영 상관없이 돼요. 글자 키(q, t, e, r, i)는 영문 상태에서 눌러요 (한글 상태면 q가 ㅂ으로 들어가 안 먹어요)
• 퀴즈는 답을 적고 Enter만 누르면 다음 문제로 넘어가요
• Windows는 작업 폴더에서 켜 주세요: cd ~\practice 후 claude
  (관리자 PowerShell의 기본 위치인 System32에서 켜면 파일이 임시 폴더에 생겨요)
• 노트는 기본으로 가장 저렴한 haiku 모델이 써요. 설명 수준(초급/중급/고급), 자동 노트 끄기, 노트에서 뺄 파일은 /config 의 learn-notes 항목에서 바꿀 수 있어요
• 한글 명령도 돼요: /learn 복습 · 퀴즈 · 정리 · 질문 · 기록 · 보고서 · 도움말
• 대화창에 "오늘 배운 거 알려 줘"라고 그냥 물어봐도 돼요

📎 자세한 설명
• 안내서 PDF (모드 개념부터 기능·활용 팁까지)
  https://github.com/Owen-YC/learn-notes/blob/main/docs/team/learn-notes-guide.pdf
• 소개 PPT (바로 내려받기)
  https://github.com/Owen-YC/learn-notes/raw/main/docs/team/learn-notes-intro.pptx
• 저장소·사용 데모 영상
  https://github.com/Owen-YC/learn-notes

써 보다가 막히거나 이상한 게 보이면 화면을 캡처해서 편하게 보내 주세요. 이런 기능 있으면 좋겠다는 의견도 환영이에요 🙌
```

## 개발

```
.claude-plugin/plugin.json        매니페스트 · 설정 항목(userConfig)
.claude-plugin/marketplace.json   이 저장소를 마켓플레이스로 쓰게 하는 목록
hooks/hooks.json                  훅 모듈 위치
hooks/register.tsx                훅: 변경 수집 · 노트 작성 · 패널 · /learn · 학습 기록 도구
hooks/notes.ts                    순수 함수: diff 자르기·되읽기 · 비밀값 가림·뺄 파일 · 전/후와 바뀐 낱말 · 프롬프트 · 팀 규칙 파일 · 일지 · 간격 반복 · 보고서 · Anki
types/index.d.ts                  $.state 계약
tests/*.test.ts                   claude plugin test로 도는 검사
```

- 검사: `claude plugin validate .` · `claude plugin test .`
- 고쳐 보며 쓰기: `claude --plugin-dir .`로 열면 파일을 고칠 때마다 대화 중에도 다시 불러옵니다. 이때 settings.json의 설정 이름은 `learn-notes@learn-notes`가 아니라 `learn-notes`(또는 `learn-notes@inline`)입니다.
- 타입 검사: `tsconfig.json`이 가리키는 `.claude-plugin/types/`(Claude Code가 모드 작업 폴더에 만들어 두는 타입 정의)가 있을 때 `npx tsc --noEmit -p .`

버그나 제안은 [Issues](https://github.com/Owen-YC/learn-notes/issues)에 남겨 주세요.
